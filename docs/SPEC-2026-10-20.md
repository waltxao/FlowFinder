## 1. 面板拖动模型（#1）

### 1.1 核心模型

**拖操作面板 = 拖它当前那个标签。** 面板被拖空（只剩 1 个标签且被拖走）时面板消失，表现为合并。

### 1.2 起手区（命中测试）

| 区域 | 按下拖动 | 说明 |
|---|---|---|
| 工具栏空白 | 拖面板 | 按钮、搜索框、下拉控件仍走自身逻辑 |
| 标签条空白 | 拖面板（单标签时等同拖标签） | 标签本身仍是拖标签 |
| 文件列表的文件行 | 拖文件 / 单击选中 | **不参与面板拖动** |
| 文件列表的空白处 | **框选**（保留访达习惯） | **不参与面板拖动** |
| 面板左右边缘 6pt | 调宽（见 §7） | 不参与面板拖动 |

### 1.3 抬起形态

- 拖动开始时对整块面板（工具栏 + 标签条 + 列表 + 详情浮层）做一次快照
- 快照以 **1:1 尺寸**、0.55 不透明度、带投影的**无边框浮层面板**跟随鼠标
- 原位置留 **虚线占位框**（1px 虚线，强调色 50%）
- 浮层必须是独立 `NSPanel`（`ignoresMouseEvents = true`），否则拖出主窗口后看不见

> **实施补记**：最终没有走 `NSDraggingSession`，改用**窗口级 local monitor 自管拖拽**
> （`UI/FFPaneDrag.swift` 的 `FFPaneDragController`）。原因见 §1.7。

### 1.4 落点与结果（状态机）

| 源状态 | 落点 | 结果 |
|---|---|---|
| 单面板 · 1 个标签 | 任意 | **整个窗口跟随拖动**（此时拖面板＝拖窗口） |
| 单面板 · ≥2 个标签 | 窗口右半区 | 当前标签拆成右面板；左面板退回相邻标签；转双面板 |
| 单面板 · ≥2 个标签 | 窗口外 | 当前标签拆成独立新窗口；左面板退回相邻标签 |
| 单面板 · ≥2 个标签 | 其它窗口内区域 | 回原位（浮层滑回 + 淡出） |
| 双面板 · 源面板 1 个标签 | 对面面板任意处 | 源面板被搬空 → 消失，标签并入对面 → **转单面板** |
| 双面板 · 源面板 ≥2 个标签 | 对面面板任意处 | 只搬当前标签；源面板退回相邻标签；**仍是双面板** |
| 双面板 · 源面板 1 个标签 | 窗口外 | 拆成新窗口，源面板消失（若对面还有内容则保留单面板） |
| 任意 | 拖过 4pt 阈值前松手 | 视为点击，不进入拖动 |

**判定顺序**：窗口外 → 新窗口；对面面板范围内 → 并入；窗口右半区（双面板时已被占用，不适用）→ 新建右面板；其余 → 回原位。

### 1.5 窗口拖动

- **允许**：侧栏任意空白、面板卡片四周的 8pt 留白
- **禁止**：操作面板的列表区、标签条、工具栏按钮上
- 实现：窗口 `isMovable = false` 关掉系统对标题栏/背景的拖动，窗口拖动由
  `FFWindowDrag`（侧栏、卡片留白）与 `FFPaneDragController`（单面板单标签时的退化）自己接管。

### 1.6 明确不做

- 不做「面板上下边缘拖动」（由窗口高度接管）
- 不做「拖到窗口左侧生成左面板」（单面板时只有右侧落点）
- 不做「拖动时实时重排布局预览」（只在落点位置显示提示框）

### 1.8 修订后的拖动模型（2026-10-20 上午，最终版）

用户反馈：上一版「按住操作面板拖走窗口」的判断依据仍然混乱。
根因是**同一个区域按下去的结果取决于当前状态**（单栏单标签时拖工具栏＝拖窗口）。
最终模型把三件事彻底分开：

| 区域 | 按住拖动 |
|---|---|
| 侧栏空白 | **拖窗口** |
| 面板卡片四周 8pt 留白 | **拖窗口** |
| 标签条空白 | **拖窗口**（标签条已提到标题栏带，性质等同标题栏） |
| 标签条上的**标签**，在条内（含 20pt 缓冲） | **重排标签**，面板不动 |
| 标签条上的**标签**，拖出缓冲 | **搬整块面板**，1:1 浮层跟随 |
| 工具栏、文件列表 | **不产生任何拖动**（给按压反馈） |
| 文件列表空白处 | 框选（不变） |

**关键变化**：

1. **标签条常显**——只有 1 个标签时也显示（原来 `store.count > 1` 才显示）。
2. **标签条从卡片顶部提到窗口标题栏带**，与红绿灯同一行（0–28pt）。
   卡片顶部因此重新变成工具栏 Row1，#4 的对齐基准也随之改为「红绿灯 ↔ 标签条」。
3. **拖标签 = 搬整块面板**（不是搬标签内容）。
   面板在窗口内只有 1 个或 2 个槽位，搬动即换槽。
4. **不再有「单栏单标签退化成拖窗口」**——窗口拖动只走上面表里那三处白名单。
5. **落点规则**（整块面板的移动）：

| 落点 | 结果 |
|---|---|
| 同一窗口的空槽（单栏时的右半区） | 面板移过去 → 双栏 |
| 已被占用的槽（对面面板） | 两块面板**合并成一个**（标签并集）→ 窗口变单栏 |
| 窗口外 | 拆成独立新窗口 |
| 其它 | 回原位 |

6. **手势分界用 20pt 缓冲区**：指针在标签条矩形外扩 20pt 内仍算「条内重排」，
   真正离开缓冲区才算拖出。标签条只有 28pt 高，无缓冲会导致垂直抖动误触发、
   重排几乎无法完成。
7. **拖影仍是 1:1 整块面板浮层**（0.55 不透明 + 投影 + 原位置虚线占位框）——
   语义是「整块面板在移动」，小卡片会表达成「只有标签在飞」。

### 1.9 为什么标签拖动要自管、不能用 NSDraggingSession

标签条在标题栏带内，那一带的 `mouseDown` 会被系统标题栏抢走（先于内容视图），
所以「拖标签」与「拖窗口」必须共用**窗口级 local monitor**：
monitor 在事件分发前拦下，用 `contentView.hitTest` 判断命中的是标签还是标签条空白，
再决定是重排、搬面板、还是拖窗口。

`NSDraggingSession` 只适合「条内重排」这一种手势（源就是标签本身）；
「出条搬面板」需要 1:1 浮层 + 自己判定落点，做不到。
因此**两种手势统一自管**，不再混用 `NSDraggingSession`，
`PaneTabDropReceiver` 与 `PaneTabDragContext` 的标签拖放路径随之退役。

### 1.10 架构收拢：交互决策表（2026-10-20 上午第三轮，最终版）

用户反馈「问题有点多」，并提出是否改用 Chromium 组件。

**Chromium 路线的核查结论**（决定了不走这条路）：

| 设想 | 事实 |
|---|---|
| Chromium 有成熟的标签页管理组件 | `TabStrip` / `TabDragController` 在 `chrome/browser/ui/views/tabs/`，深度绑定 `WebContents`、`TabStripModel`、`content::` 通知机制与 C++ Views 框架，**不是可复用独立库** |
| 摘出来接到 AppKit 上 | 做不到。Chromium 唯一可嵌入形态是 CEF / Electron，等于整体重写 |
| Rust 核心受不受影响 | 不受。24 模块 / 13.5k 行全是文件操作、搜索、FSEvents、缩略图、去重，与 UI 框架无关 |

**结论：保留原生 AppKit + Rust 核心，只借鉴 Chromium 的「把拖拽判定收进单一状态机」这一做法。**
Chromium 值得借鉴的不是 TabStrip 代码，而是 `TabDragController` 里只有三件事：
当前贴在哪个条上 / 能不能分离 / 落点算哪个条——没有散落各处的 if，所以它不漏。

#### 1.10.1 问题的真实结构

四轮返工不是四个独立 bug，而是同一个架构问题的四次显形：

| 症状 | 显形层 |
|---|---|
| 按住面板拖 → 拖走整个窗口 | `mouseDownCanMoveWindow`（AppKit 默认对不透明视图返回 true） |
| 单栏单标签时拖面板 = 拖窗口 | 状态分支散在拖拽控制器里 |
| 卡片上边缘 0 / 下边缘 8 | Auto Layout 约束（几何与判定互相牵连） |
| 侧栏隐藏后标签不避让 | `applySidebarHiddenToolbarInset()` 只覆盖 toolbar |

共同点：全部是「同一区域，按下去的行为取决于当下状态」，而每次都靠「再加一个 if」修补。

**当前散落规模**（改造前实测）：

- `mouseDownCanMoveWindow` 覆写 **11 处**，分布 9 个文件
- `hitTest` 覆写 **11 处**，分布 9 个文件
- 两套系统（AppKit 默认行为 + 我们的判定）互相覆盖

#### 1.10.2 决策表结构

**区域按语义分 4 种**（不是按视图清单列 11 个——那样表会膨胀到几百行，
且「侧栏行 vs 侧栏空白」这类细分仍要靠 hitTest 归并猜，本质只是把 if 换个地方堆）：

| 区域 | 含义 | 包含 |
|---|---|---|
| `.window` | 窗口区 | 侧栏空白、面板卡片四周 8pt 留白 |
| `.title` | 标题区 | 标签条（含空白与标签本体之外的部分）、红绿灯带 0..28 |
| `.panel` | 面板区 | 工具栏、文件列表、详情栏浮层、侧栏行 |
| `.tab` | 标签本体 | 标签胶囊（唯一能拖面板的把手） |

**意图 5 种**：

| 意图 | 触发条件 |
|---|---|
| `.dragWindow` | 区域 = `.window`；或区域 = `.title` 且命中标签条空白 |
| `.dragPane` | 区域 = `.tab` 且指针已离开标签条 20pt 缓冲 |
| `.reorderTab` | 区域 = `.tab` 且指针仍在 20pt 缓冲内 |
| `.activateTab` | 区域 = `.tab` 且按下后未移动（点击） |
| `.marqueeSelect` | 区域 = `.panel` 且命中文件列表空白 |

**决策函数是纯函数**，不依赖任何 AppKit 对象：

```swift
func intent(region: FFRegion, state: FFInteractionState) -> FFIntent
```

状态只含决策真正需要的三个维度：
`sidebarVisible`（决定标签条避让量）、`singlePane`（决定拖面板的落点语义）、
`pointerInsideTabBuffer`（决定重排 vs 搬面板）。

#### 1.10.3 验证方式（Swift XCTest 通道在本机不可用）

本工程 `xcodebuild test` 会挂死（~340s 超时），用 `git worktree` 跑基线同样失败
——是环境问题不是代码问题，但它在本项目里就是不可用的验证通道。

**采用三层**：

1. **纯函数 + 启动穷举自检**（主保障）：`FF_SELFTEST=1` 启动时遍历所有
   「区域 × 意图 × 关键状态」组合，逐条断言并打印。漏一行就是 FAIL。
   与现有已跑通 8 项的自检通道一致。
2. **合成鼠标事件真拖验收**（保底）：CGEvent 在真实坐标上点/拖，
   比对窗口位置、面板内容、日志结论。这验的是真实事件链，
   **包含 AppKit 默认行为——正是之前四个 bug 的藏身处**。
   注意 TCC 授权弹窗会吃掉所有合成点击，必须先点掉「允许」。
3. XCTest 代码可写但不当依赖。

#### 1.10.4 本轮两个布局修复

**① 卡片上边缘（顶部留白 0、底部 8 → 四周统一 8）**

根因：`MainWindowController.swift:835` 的 `content.topAnchor == wrapper.topAnchor`（0）
是上一轮「标签条塞进卡片内部」的副产物。修法采用**标签条真正浮到窗口顶 0..28，
卡片本体四周统一 8pt**：

- 标签条脱离卡片容器，成为窗口级浮层（`titlebarAppearsTransparent` 让它透出来）
- 标题区 = 窗口顶部 0..28 整条，跨侧栏与操作区
- 卡片顶部重新有 8pt 留白 → 发光视图的 `topEdgeOutset` 恢复为 8
  （原来为 0 是为了「卡片贴顶时不外扩」，现在卡片不再贴顶）
- 红绿灯与标签条中心都是 14pt，#4 的对齐基准成立

**② 侧栏隐藏后标签条避让**

根因：`applySidebarHiddenToolbarInset()` 只给 toolbar 设了 `leadingInset = 106`，
**标签条完全没有对应机制**（且标签条当时在卡片内部，卡片在侧栏隐藏后移到 x=8，
第一个标签直接被红绿灯 13..70 与「显示侧栏」开关 72..96 压住）。

修法：**标签条与工具栏共用同一个避让量**——侧栏可见时从卡片左缘起，
侧栏隐藏时从 x=106 起。两处由同一个函数计算，改一处两处生效。

#### 1.10.5 决策表与既有行为的一致性

收拢后必须保持的行为（全部有自检断言）：

| 场景 | 意图 |
|---|---|
| 侧栏空白拖动 | 拖窗口（位移与鼠标一致） |
| 面板卡片 8pt 留白拖动 | 拖窗口 |

### 1.11 标签与操作面板的焊接（2026-10-20 上午第四轮，最终版）

用户反馈：标签浮在面板上方、与面板断开，发光也不跟标签。要求「标签和操作面板连接起来，
发光边缘也要跟着，适当调宽标题栏保证标签上有间隙」。

**问题成因**（实测几何）：

| 元素 | 旧值 | 后果 |
|---|---|---|
| 标题带 | 0..28 | 标签胶囊 3..25 |
| 面板卡片顶边 | 36 | 标签底边 25 与卡片顶边 36 之间空 **11pt** |
| 发光 | 只描卡片矩形（`topEdgeOutset = 36`） | 完全不跟标签 |

#### 决策（五轮确认）

| 项 | 结论 |
|---|---|
| 连接形态 | **面板顶边凸出标签**（文件夹标签式）：面板顶边保持完整，标签从顶边向上凸出，底边与面板焊死 |
| 多标签 | **只有活动标签焊死**；非活动是悬浮胶囊，底边离面板顶边 6pt、比活动矮 6pt |
| 标题带高 | **36pt** → 标签上方间隙 8pt（与左右下留白 8 同值），卡片顶边仍为 36，位置不动 |
| 活动标签底色 | **与面板同色**（活动态靠「无接缝 + 加粗 + 比非活动高 6pt」表达，不用强调色） |
| 接缝圆角 | 标签顶部 **r1 = 10**，根部内凹 **r2 = 8** |

#### 几何（wrapper 坐标系，原点左下）

| 量 | 值 | 说明 |
|---|---|---|
| 标题带 | 0..36（距窗口顶） | `titleBandHeight = 36` |
| 活动标签 | y 从 8 到 36，高 28 | 底边 = 面板顶边，焊死 |
| 非活动标签 | y 从 8 到 30，高 22 | 底边离面板顶边 6pt |
| 标签左缘 | 距面板左缘 **20pt** | 面板圆角 16 + 4，否则根部内凹与圆角打架 |
| 面板卡片 | 顶边 36，左/右/下各 8 | 与旧版一致，位置不动 |

#### 发光路径

发光从「只描卡片矩形」改成**沿「面板 + 活动标签」的合并轮廓**：

- 沿面板顶边向标签走 → 根部 r2 内凹 → 标签左右竖边 → 标签顶部 r1 圆角 → 另一侧根部内凹
- 沿面板左右底三边走原 16pt 圆角
- 描边仍是 14 层同心、1→13pt、峰值 0.055（不变）
- 非活动标签**不参与**合并轮廓（它悬在上方，与面板不相接）

#### 实现要点（避免踩坑）

1. **根部内凹在标签视图之外**——它位于「标签左缘再往左 r2」与「面板顶边再往上 r2」的
   那块区域里，标签自身画不出来。因此新增一层 `PaneTabStripBackdrop`（标签条的子视图、
   位于所有标签之下），由它填充「标签 + 两处内凹」的轮廓；标签本身背景透明。
2. **发光与背板共用同一条路径构造器**（`FFTabSilhouette`），避免两处各画一套导致对不上。
3. **面板卡片不能自绘缺口**（SquircleView 有 masksToBounds）；靠背板与卡片的颜色一致
   在视觉上合并——因此活动标签必须与面板同色（这条是几何决定的，不是审美偏好）。

### 1.12 第四轮：点击失效修复 + 跨窗口拖出拖回（2026-10-20 中午）

用户反馈两件事：① 单窗口多标签时，标签拖出后再拖入变成双窗口的流程没实现；
② **软件开启时整个操作系统的点击都有问题**。

#### 1.12.1 点击失效的两条根因（已定位到代码）

| 链路 | 根因 | 表现 |
|---|---|---|
| 应用内 | `FFPaneDragController.handleDown` 对 `.pressFeedback` 意图 **返回 nil**（吞掉 mouseDown 与 mouseUp）。决策表把「工具栏 / 文件列表 / 侧栏行」全映射到 pressFeedback | 点文件、点工具栏按钮、点侧栏行全部没反应 |
| 系统级 | 同上：press 模式下**每一次点击的 mouseDown 都被吞**。若指针拖出窗口外再松手，mouseUp 不回到我们 → 系统认为鼠标仍处于按下状态 → 之后所有 App 的点击都被当作拖拽续接 | 切到别的 App 也点不动，要再点一下才恢复 |

第三个 bug（叠加在上面）：`FFPaneDragController` 是**全局单例**，而 `install(for:)` 由每个窗口调用
——第二个窗口创建时 `self.window` 被覆盖，于是只有最后创建的窗口的点击会被接管，
其余窗口的拖动与反馈全部失效。

#### 1.12.2 修复方案

| 项 | 方案 |
|---|---|
| press 反馈 | **不再消费事件**：`.pressFeedback` 只做 0.5pt 下沉的视觉反馈，mouseDown / mouseUp 都原样放行，控件照常响应 |
| 单例覆盖 | 保留**单一 app 级 monitor**（避免多 monitor 的调用顺序问题），但事件按 `event.window` 路由到对应窗口的宿主，不再用单一的 `self.window` |
| 失焦复位 | 监听 `NSApplication.didResignActiveNotification`：复位拖拽状态、结束浮层、移除按压反馈；若当时处于「已消费 mouseDown」的状态，补发一次 mouseUp 释放系统端的按键状态 |
| 拖拽状态归属 | 拖拽会话（源窗口、源标签、浮层、落点高亮）挂在**会话对象**上，跨窗口时由目标窗口渲染高亮 |

#### 1.12.3 跨窗口拖出拖回（六轮确认）

| 项 | 结论 |
|---|---|
| 拖出搬什么 | **只搬当前标签**（原窗口保留其余标签，仍是单栏）。推翻了上一轮「搬整块面板」的模型 |
| 拖回落点 | **按落点分流**：落在标签条上 = 并成该面板的标签（仍单栏）；落在操作区左/右半区 = 拆成左右两块面板 |
| 源窗口 | 面板被搬空就**自动关窗**；还有别的标签就留着 |
| 跨窗口反馈 | 拖到另一个窗口上时，**高亮落点区**（半透明色块：右/左半区一块，标签条一条），松手前就知道会变成什么 |
| 目标窗口宽度 | 变双面板时**窗口自动加宽**到能放下两块（最小 1060），侧栏宽度与原面板宽度都不变，拖回的面板占新增空间 |
| 旧模型作废 | 「拖拽永远不会增加栏数」这条裁定作废——跨窗口拖回可以增栏 |

#### 1.12.4 顺带定的三件事

| 项 | 结论 |
|---|---|
| 面板切换动画 | 改为**真位移**：放弃 `NSSplitView` 自己排两块面板的 frame，改由应用自管布局（拖边调宽、宽度记忆一并重写） |
| 三控制图标 | **拆开**：隐藏侧栏紧跟红绿灯（与窗口控制同组），主题与单双窗靠侧栏右缘（右缘距 12）。推翻 2026-10-19 #10 的「三者都紧跟红绿灯」 |
| 启动卡顿 | **渲染不等标签**：`warmCache` 已在后台预热，但渲染与预热抢跑导致主线程同步读 xattr。改为行先出（标签位留空），预热完成后只刷新受影响行 |

### 1.7 实施补记：两个 AppKit 层面的根因

规格初稿只把「按住操作面板拖动变成拖窗口」归因到 `isOpaque`，实现时发现**有两层**：

**第一层：`NSView.mouseDownCanMoveWindow` 的默认值**
AppKit 的默认实现对**不透明视图返回 true**（`NSView.isOpaque` 默认就是 true）。
于是工具栏里的 `NSStackView`、占位视图、面板卡片这些「纯排版容器」全都成了窗口拖动区。
修法是显式覆写该属性为 `false`（新增 `FFNonDragView` / `FFNonDragStackView` 两个基类），
而不是去改 `isOpaque`——后者有主题重绘的副作用。

**第二层：窗口顶部 28pt 是系统标题栏的拖动区**
这一层更隐蔽：工具栏第一行（窗口 y 4–40）几乎完全落在标题栏带内，
标题栏会**先于内容视图**吃掉 `mouseDown`，于是那一带既拖不动面板、也拖不动内容。
把 `mouseDownCanMoveWindow` 改成 false 之后，这一带变成**死区**（什么都不发生）。

真正的解法是 `NSWindow.isMovable = false`（官方文档：关掉服务端拖动，
并建议应用自行处理 mouseDown/mouseDragged/mouseUp）+ **窗口级 local monitor**：
monitor 在事件分发**之前**就能拿到 `mouseDown`，用 `contentView.hitTest` 判断
命中的是不是「工具栏空白 / 标签条空白」，是就接管成「拖面板」。

这也决定了拖拽**不能**用 `NSDraggingSession`：
该 API 要求拖拽源就是收到 `mouseDown` 的视图，而标题栏带内的 mouseDown 根本到不了内容视图。
自管拖拽还顺带省掉了 pasteboard 与 `NSDraggingDestination`。

## 11. 风险与取舍

1. **测试通道不可用**：本工程 `xcodebuild test` 在用户机器上挂死（见 AUDIT §5）。本轮的回归只能靠 `FF_SELFTEST` 扩展 + 真实截图 + 像素核对，属于降级验证，需在交付说明中如实标注。
2. **#1 改动面最大**：涉及 `mouseDownCanMoveWindow`、拖放会话、独立浮层窗口、标签状态机、单双窗切换。建议单独一批，做完即验，不与其他项混。
3. **#3 与上一轮冲突**：上一轮把四列合成两列，本轮恢复四列。旧的 `metaCol`（`__sort_size__` / `__sort_type__` 占位 key）逻辑要整体替换为「每列一个 identifier」，排序箭头按列自身 key 匹配，不再需要占位 key。
4. **#5 需要自绘窗口遮罩**：`NSWindow` 的系统圆角无法改成超椭圆，要加一层 mask。全屏与最大化状态需单独处理，否则会出现黑边。
