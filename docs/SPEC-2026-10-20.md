## 1. 面板拖动模型（#1）

### 1.1 核心模型

**拖操作面板 = 拖它当前那个标签。** 面板被拖空（只剩 1 个标签且被拖走）时面板消失，表现为合并。

### 1.2 起手区（命中测试）

| 区域 | 按下拖动 | 说明 |
|---|---|---|
| 工具栏空白 | 拖面板 | 按钮、搜索框、下拉控件仍走自身逻辑 |
| 标签条空白 | 拖面板（单标签时等同拖标签） | 标签本身仍是拖标签 |
| 文件列表的文件行 | 拖文件 / 单击选中 | **不参与面板拖动** |
| 文件列表的空白处 | **框选**（保留访达习惯） | **不参与面板拖动** |
| 面板左右边缘 6pt | 调宽（见 §7） | 不参与面板拖动 |

### 1.3 抬起形态

- 拖动开始时对整块面板（工具栏 + 标签条 + 列表 + 详情浮层）做一次快照
- 快照以 **1:1 尺寸**、0.55 不透明度、带投影的**无边框浮层面板**跟随鼠标
- 原位置留 **虚线占位框**（1px 虚线，强调色 50%）
- 浮层必须是独立 `NSPanel`（`ignoresMouseEvents = true`），否则拖出主窗口后看不见

> **实施补记**：最终没有走 `NSDraggingSession`，改用**窗口级 local monitor 自管拖拽**
> （`UI/FFPaneDrag.swift` 的 `FFPaneDragController`）。原因见 §1.7。

### 1.4 落点与结果（状态机）

| 源状态 | 落点 | 结果 |
|---|---|---|
| 单面板 · 1 个标签 | 任意 | **整个窗口跟随拖动**（此时拖面板＝拖窗口） |
| 单面板 · ≥2 个标签 | 窗口右半区 | 当前标签拆成右面板；左面板退回相邻标签；转双面板 |
| 单面板 · ≥2 个标签 | 窗口外 | 当前标签拆成独立新窗口；左面板退回相邻标签 |
| 单面板 · ≥2 个标签 | 其它窗口内区域 | 回原位（浮层滑回 + 淡出） |
| 双面板 · 源面板 1 个标签 | 对面面板任意处 | 源面板被搬空 → 消失，标签并入对面 → **转单面板** |
| 双面板 · 源面板 ≥2 个标签 | 对面面板任意处 | 只搬当前标签；源面板退回相邻标签；**仍是双面板** |
| 双面板 · 源面板 1 个标签 | 窗口外 | 拆成新窗口，源面板消失（若对面还有内容则保留单面板） |
| 任意 | 拖过 4pt 阈值前松手 | 视为点击，不进入拖动 |

**判定顺序**：窗口外 → 新窗口；对面面板范围内 → 并入；窗口右半区（双面板时已被占用，不适用）→ 新建右面板；其余 → 回原位。

### 1.5 窗口拖动

- **允许**：侧栏任意空白、面板卡片四周的 8pt 留白
- **禁止**：操作面板的列表区、标签条、工具栏按钮上
- 实现：窗口 `isMovable = false` 关掉系统对标题栏/背景的拖动，窗口拖动由
  `FFWindowDrag`（侧栏、卡片留白）与 `FFPaneDragController`（单面板单标签时的退化）自己接管。

### 1.6 明确不做

- 不做「面板上下边缘拖动」（由窗口高度接管）
- 不做「拖到窗口左侧生成左面板」（单面板时只有右侧落点）
- 不做「拖动时实时重排布局预览」（只在落点位置显示提示框）

### 1.8 修订后的拖动模型（2026-10-20 上午，最终版）

用户反馈：上一版「按住操作面板拖走窗口」的判断依据仍然混乱。
根因是**同一个区域按下去的结果取决于当前状态**（单栏单标签时拖工具栏＝拖窗口）。
最终模型把三件事彻底分开：

| 区域 | 按住拖动 |
|---|---|
| 侧栏空白 | **拖窗口** |
| 面板卡片四周 8pt 留白 | **拖窗口** |
| 标签条空白 | **拖窗口**（标签条已提到标题栏带，性质等同标题栏） |
| 标签条上的**标签**，在条内（含 20pt 缓冲） | **重排标签**，面板不动 |
| 标签条上的**标签**，拖出缓冲 | **搬整块面板**，1:1 浮层跟随 |
| 工具栏、文件列表 | **不产生任何拖动**（给按压反馈） |
| 文件列表空白处 | 框选（不变） |

**关键变化**：

1. **标签条常显**——只有 1 个标签时也显示（原来 `store.count > 1` 才显示）。
2. **标签条从卡片顶部提到窗口标题栏带**，与红绿灯同一行（0–28pt）。
   卡片顶部因此重新变成工具栏 Row1，#4 的对齐基准也随之改为「红绿灯 ↔ 标签条」。
3. **拖标签 = 搬整块面板**（不是搬标签内容）。
   面板在窗口内只有 1 个或 2 个槽位，搬动即换槽。
4. **不再有「单栏单标签退化成拖窗口」**——窗口拖动只走上面表里那三处白名单。
5. **落点规则**（整块面板的移动）：

| 落点 | 结果 |
|---|---|
| 同一窗口的空槽（单栏时的右半区） | 面板移过去 → 双栏 |
| 已被占用的槽（对面面板） | 两块面板**合并成一个**（标签并集）→ 窗口变单栏 |
| 窗口外 | 拆成独立新窗口 |
| 其它 | 回原位 |

6. **手势分界用 20pt 缓冲区**：指针在标签条矩形外扩 20pt 内仍算「条内重排」，
   真正离开缓冲区才算拖出。标签条只有 28pt 高，无缓冲会导致垂直抖动误触发、
   重排几乎无法完成。
7. **拖影仍是 1:1 整块面板浮层**（0.55 不透明 + 投影 + 原位置虚线占位框）——
   语义是「整块面板在移动」，小卡片会表达成「只有标签在飞」。

### 1.9 为什么标签拖动要自管、不能用 NSDraggingSession

标签条在标题栏带内，那一带的 `mouseDown` 会被系统标题栏抢走（先于内容视图），
所以「拖标签」与「拖窗口」必须共用**窗口级 local monitor**：
monitor 在事件分发前拦下，用 `contentView.hitTest` 判断命中的是标签还是标签条空白，
再决定是重排、搬面板、还是拖窗口。

`NSDraggingSession` 只适合「条内重排」这一种手势（源就是标签本身）；
「出条搬面板」需要 1:1 浮层 + 自己判定落点，做不到。
因此**两种手势统一自管**，不再混用 `NSDraggingSession`，
`PaneTabDropReceiver` 与 `PaneTabDragContext` 的标签拖放路径随之退役。

### 1.7 实施补记：两个 AppKit 层面的根因

规格初稿只把「按住操作面板拖动变成拖窗口」归因到 `isOpaque`，实现时发现**有两层**：

**第一层：`NSView.mouseDownCanMoveWindow` 的默认值**
AppKit 的默认实现对**不透明视图返回 true**（`NSView.isOpaque` 默认就是 true）。
于是工具栏里的 `NSStackView`、占位视图、面板卡片这些「纯排版容器」全都成了窗口拖动区。
修法是显式覆写该属性为 `false`（新增 `FFNonDragView` / `FFNonDragStackView` 两个基类），
而不是去改 `isOpaque`——后者有主题重绘的副作用。

**第二层：窗口顶部 28pt 是系统标题栏的拖动区**
这一层更隐蔽：工具栏第一行（窗口 y 4–40）几乎完全落在标题栏带内，
标题栏会**先于内容视图**吃掉 `mouseDown`，于是那一带既拖不动面板、也拖不动内容。
把 `mouseDownCanMoveWindow` 改成 false 之后，这一带变成**死区**（什么都不发生）。

真正的解法是 `NSWindow.isMovable = false`（官方文档：关掉服务端拖动，
并建议应用自行处理 mouseDown/mouseDragged/mouseUp）+ **窗口级 local monitor**：
monitor 在事件分发**之前**就能拿到 `mouseDown`，用 `contentView.hitTest` 判断
命中的是不是「工具栏空白 / 标签条空白」，是就接管成「拖面板」。

这也决定了拖拽**不能**用 `NSDraggingSession`：
该 API 要求拖拽源就是收到 `mouseDown` 的视图，而标题栏带内的 mouseDown 根本到不了内容视图。
自管拖拽还顺带省掉了 pasteboard 与 `NSDraggingDestination`。

## 11. 风险与取舍

1. **测试通道不可用**：本工程 `xcodebuild test` 在用户机器上挂死（见 AUDIT §5）。本轮的回归只能靠 `FF_SELFTEST` 扩展 + 真实截图 + 像素核对，属于降级验证，需在交付说明中如实标注。
2. **#1 改动面最大**：涉及 `mouseDownCanMoveWindow`、拖放会话、独立浮层窗口、标签状态机、单双窗切换。建议单独一批，做完即验，不与其他项混。
3. **#3 与上一轮冲突**：上一轮把四列合成两列，本轮恢复四列。旧的 `metaCol`（`__sort_size__` / `__sort_type__` 占位 key）逻辑要整体替换为「每列一个 identifier」，排序箭头按列自身 key 匹配，不再需要占位 key。
4. **#5 需要自绘窗口遮罩**：`NSWindow` 的系统圆角无法改成超椭圆，要加一层 mask。全屏与最大化状态需单独处理，否则会出现黑边。
