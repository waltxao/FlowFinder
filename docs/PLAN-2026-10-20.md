## 0. 分批理由

四项打磨（#2 #6 #9 #10）与两项重做（#3 #4）互不冲突，可以后置。
真正会互相踩的是 **#1 面板拖动** 与 **#8 面板边缘调宽** —— 两者都在抢同一批鼠标事件和同一条分栏边界，必须同批做、一次验完。
**#3 列表四列** 与 **#10 中线对齐** 改的是同一批单元格，也必须同批。

| 批次 | 内容 | 依赖 | 预估改动面 |
|---|---|---|---|
| **A** | #1 面板拖动模型 + #8 边缘调宽 | 无 | 大（事件路由 / 拖放 / 分栏） |
| **B** | #3 列表四列与可选列 + #10 中线对齐 | 无 | 中（FileListView / FileEntry） |

| **D** | #6 侧栏图标 + #9 发光 + #2 切换动画 | A 完成后做 #2 | 小（图标 / 绘制 / 动画） |

顺序：A → B → C → D。每批独立构建、独立截图、独立提交。

## 批次 A · 拖动模型与边缘调宽

### A1 关掉误拖窗口

**文件**：`UI/FFCommon.swift`（`FFOpaqueContainerView`）
覆写 `mouseDownCanMoveWindow` 返回 `false`。这是「按住面板拖窗口」的根因（`isOpaque` 被覆写为 false 导致 AppKit 默认放行）。

**验证**：按住列表空白拖动 → 出现框选，窗口不动。

### A2 窗口拖动的合法区域

**文件**：`UI/MainWindowController.swift`、`UI/SidebarView.swift`
- 侧栏空白：`mouseDownCanMoveWindow` 返回 `true`，`mouseDown` 里 `window?.performDrag(with:)`
- 窗口四边 8pt 留白：由 `FFWindowDragHandleView` 薄边视图承接
- 单面板单标签时，工具栏空白也放行窗口拖动（此时面板拖动＝窗口拖动）

**验证**：侧栏空白拖动移窗；列表区拖动不移窗。

### A3 面板拖动会话

**新文件**：`UI/FFPaneDragController.swift`
- 起手：工具栏/标签条空白 `mouseDown` → 记录起点；移动超 4pt 阈值进入拖动
- 快照：`bitmapImageRepForCachingDisplay` + `cacheDisplay` 抓整块面板
- 浮层：无边框 `NSPanel`（`ignoresMouseEvents = true`、`level = .floating`），1:1 尺寸，`alphaValue = 0.55`
- 原位占位：`FFPanePlaceholderView`，1px 虚线，强调色 30%
- 落点判定：窗口外 / 对面面板内 / 窗口右半区 / 其它

**验证**：起手后浮层跟随，原位置出现虚线框。

### A4 落点状态机

**文件**：`UI/FFPaneDragController.swift`、`UI/MainWindowController+Tabs.swift`
按 SPEC §1.4 实现四条分支：拆右面板、拆新窗口、并入对面、回原位。
并入对面时复用现有 `PaneTabDropReceiver` 的 `move` 语义（同 side 不 `insert`）。

**验证**：`FF_SELFTEST` 新增 4 条断言，覆盖四种落点。

### A5 面板边缘调宽

**文件**：`UI/MainWindowController.swift`（`FFSplitView`）、新 `UI/FFPaneResizeHandle.swift`
- 删掉 `FFDividerGlowMath` 相关的分隔发光与 hover 高亮
- 面板左右边缘 6pt 热区，`resizeLeftRight` 光标
- 左面板左缘 → `sidebar_width`；中缝两侧 → 左宽右窄（窗口不变）
- 上下边缘不响应

**验证**：中缝无发光；拖左侧改侧栏宽；拖中缝左宽右窄；拖上下无反应。

### A6 宽度持久化

**文件**：`UI/MainWindowController.swift`
新增 `pane_left_width` / `pane_right_width`。程序化改宽期间沿用现有 `isAdjustingPaneMode` 闸门，不写盘。

**验证**：改宽后重启保持。

## 批次 B · 列表四列与对齐

### B1 列定义重构

**文件**：`UI/FileListView.swift`
删除 `metaCol` 与 `__sort_size__` / `__sort_type__` 占位 key 机制，改为「每列一个 identifier + 各自 `sortDescriptorPrototype`」。
新增 `type` 列（`FFFileTypeText`）与独立 `size`、`modified` 列。

### B2 列模型与持久化

**新文件**：`Model/ListColumnConfig.swift`
`ListColumnConfig`: id / 标题 / 默认宽 / 最小宽 / 对齐 / 排序 key / 是否可选。
持久化 key `list_columns_v2`（显隐 + 宽度 + 顺序）。

### B3 三个入口

**文件**：`UI/FileListView.swift`（列头右键）、`UI/MainMenu.swift`（显示菜单）、`UI/PaneToolbar.swift`（视图面板）

### B4 收起顺序

**文件**：`UI/FileListView.swift`
宽度不足时按 `[可选列] → 类型 → 大小 → 修改时间` 顺序隐藏，名称永收。

### B5 中线对齐

**文件**：`UI/FileListView.swift`（`FFNameCellView` / 新 `FFTextCellView`）
所有单元格内容按 `bounds.midY` 垂直居中；图标 16/18/20 随行高，图标与文字间距 8pt。

**验证**：截图放大单行，图标与四列文字中线共线。

## 已知风险

| 风险 | 处置 |
|---|---|
| `NSPanel` 浮层在多显示器下的坐标换算 | 统一用 `NSEvent.mouseLocation`（全局坐标）+ `screen.frame` 换算，不混用窗口坐标 |
