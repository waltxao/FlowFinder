## 1. 逐条审查

### #1 软件包名改 FlowFinder，后续不再使用 FlowFinder

**现状**

| 位置                                                | 内容                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `Resources/Info.plist`                            | `CFBundleName = FlowFinder`（已是），`CFBundleExecutable = FlowFinder`                    |
| `project.pbxproj`                                 | 54 处 `FlowFinder`：target 名（345/362）、产品 fileRef、分组 path（204）                          |
| `xcshareddata/xcschemes/FlowFinderTests.xcscheme` | 15 处 BuildableReference                                                              |
| `Makefile`                                        | 11 处：`APP_DEBUG`/`APP_RELEASE`/`DESKTOP_APP` 路径（30–32）、`-target`（35）、`pkill` 模式（105） |
| `scripts/package.sh`、`package-beta.sh`            | 各 5 处（app 名、DMG 名、校验路径）                                                              |
| Swift 源码                                          | 7 处：3 个测试文件 `@testable import FlowFinder` + 2 处文件头注释                                 |
| 文档                                                | 15 个 md（README 10、HANDOVER 9、CHANGELOG 等）                                            |

**风险**

- 改 target / module 名后，测试 target 的 `TEST_HOST`、`@testable import`、scheme 必须同步，  
  漏一处就是「测试宿主起不来」或「模块找不到」。
- `.app` 改名后，桌面副本、`pkill` 模式、`make demo` 路径、DMG 名全部要跟着改，  
  否则会出现「构建成功但用户打开的仍是旧包」。
- 已安装用户的 TCC 权限与偏好按 **bundle id** 绑定。**bundle id 保持 `com.flowfinder.native`  
  不变**，改名不会丢权限；若把 id 里也去掉 native，等于新应用，偏好与权限全丢（需迁移，不建议）。
- 仓库顶层目录（`flowfinder-native`）改名会断当前会话工作目录、断文档里的绝对路径，  
  必须作为最后一步、在会话外执行。

**做法**

1. `git mv` 改名目录：`FlowFinder/` → `FlowFinder/`、`FlowFinder.xcodeproj` → `FlowFinder.xcodeproj`、  
   `FlowFinder/FlowFinder/` → `FlowFinder/FlowFinder/`、测试目录同理。
2. 改 pbxproj：target 名、产品 fileRef `path`、分组 path、`TEST_HOST`、`PRODUCT_NAME`。  
   **逐个 ID 核对，不整文件正则替换**（pbxproj 结构敏感）。
3. 改 scheme 文件名与内部 15 处引用。
4. 改 Makefile / 4 个脚本 / 3 个测试 import。
5. 全局扫文档，替换 `FlowFinder`；保留 Git 历史里的旧名。
6. 清 DerivedData，`make build` + `make swift-test`（测试通道恢复后）+ `make demo` 验证。
7. 顶层仓库目录改名单独执行，给出命令与影响清单。

### #2 侧栏图标移除，应用名下显示版本号

**现状**：`SidebarView.swift:245-285` — 32pt 图标 + 15pt bold 名称，整体高 56，顶部让出 32pt 红绿灯区。

**做法**：删 `brandIconView`（及其主题刷新监听），名称保持 15pt bold；  
下方加 11pt secondary 版本行，文案 `0.7.9 (7901)`，读 `CFBundleShortVersionString` +  
`CFBundleVersion`；品牌区高度 56 → 44；点击仍弹「关于」。

**风险**：低。唯一注意是滚动区起点（`sidebarScrollView.top = brandView.bottom + 4`）会随之上移 12pt。

### #3 红绿灯右侧加单双窗切换按钮

**现状**：`window.minSize = 1060×700`（`MainWindowController.swift:309`），  
`paneSplitView` 两张卡片（417–426）；`activePane` 记录活动侧；窗口为  
`fullSizeContentView` + 透明标题栏，红绿灯浮在侧栏顶部。

**方案**

- 按钮放在侧栏顶部安全区右侧（`top: 8, trailing: -12`，28×28，无边框，  
  symbol `rectangle.split.2x1` / `rectangle`），与红绿灯同一水平带。
- 单窗模式：隐藏非活动面板（`isHidden` + 从 arrangedSubviews 移除或 holdingPriority=0），  
  活动面板占满操作区；再点恢复双栏。
- **保留当前活动面板**；单窗下活动面板固定为可见侧，切换回来时活动侧不变。
- 最小尺寸：双窗 1060×700 不变；单窗 760×700（侧栏 160 + 450 + 边距），  
  切模式时同步 `window.minSize`，并把窗口宽度夹到合法值。
- 记忆到 `single_pane_mode`，启动恢复。

**风险**：`FFSplitView` 隐藏一侧后的分隔条与热区；键盘焦点在隐藏面板时需迁移；  
详情栏/工具栏随容器隐藏。验收：双→单→双 × 左右活动面板各一遍。

### #4 位置模块从浮层改为「位置」分区

**现状**：设备是窗口左下角浮动卡片（`MainWindowController.swift:867-907`，`FFPanelView(.card)`，  
默认折叠 48pt），数据源 `DeviceSidebarDataSource`，与「工具面板」互斥显示。  
DESIGN-SPEC M-04 明确写着「设备浮层 = 实体卡片」，**本条是对该裁定的反转**。

**方案**

- 侧栏滚动区按访达排三区：**个人收藏 → 位置 → 标签**。
- 「位置」行复用收藏行样式：磁盘图标 20pt + 名称 13pt + 容量 11pt 次级色，尾部 ⏏（可弹出卷）。
- 数据源复用 `DeviceSidebarDataSource`；卷挂载/卸载监听从 `MainWindowController`  
  迁到 `SidebarView`；删除 `devicePanel` / `devicePanelHeader` / `devicePanelStack` /  
  折叠状态 / `toggleDevicePanelExpanded` 全部代码。
- 不折叠（访达语义），卷多时随侧栏整体滚动。

**风险**：设备刷新时机、弹出确认框、外置卷权限提示；删除浮层后「工具面板互斥」逻辑要一起清理。  
DESIGN-SPEC §M-04 / §5 需同步改写。

### #5 三个栏目标题对齐

**现状**：「个人收藏」是 outline 的 group row（自绘 cell，缩进随 outline）；  
「标签」是外置 `NSTextField`（11pt medium，`SidebarView.swift:500`），  
两者字形、左缩进、行高都不同。这正是看起来不齐的原因。

**方案**：三区统一为**同一个 outline 的 group row**，共用一套 cell：  
11pt semibold + secondaryLabel、行高 20、相对侧栏左缩进 12pt、区间距 16pt。  
标签区从 `TagFlowView` 并入 outline 行（旧 P2 计划），`tagsHeaderView` / `tagsTitleLabel` 删除。

**依赖**：#4 不做，本项只能做「两块标题勉强对齐」，做完 #4 又要重排——**两项合并为一个批次**。

**风险**：收藏的拖拽重排、右键菜单、失效灰显、标签点击筛选都挂在现有 outline/数据源上，  
重构时要用 `SidebarFavoritesStoreTests`（17 项）兜底 + 手工过一遍右键菜单五项。

### #6 活动面板改为蓝色发光边缘

**现状**：`FFComponents.swift` 的 `FFActivePaneBorderView` — 1.5pt `FFAccent` 实线 + 16pt 圆角，  
`hitTest` 返回 nil（事件穿透），盖在详情栏之上。

**方案**

- 去掉硬边：外发光用 `CALayer.shadow`（color=FFAccent，radius 10，opacity 0.55，offset 0，  
  `shadowPath` 随布局更新）+ 内侧三层渐变描边（6pt@10% / 3pt@18% / 1pt@55%）。
- 保留 1pt 芯线，保证纯色模式下仍能看出边界。
- 深色模式提高外发光不透明度（0.55 → 0.7），浅色模式降低（0.45）。
- 「增强对比度」辅助功能开启时降级为 1.5pt 实线。

**风险**：阴影是离屏渲染，两面板各一层，滚动时应确认无掉帧；`shadowPath` 必须在  
`layout()` 里更新，否则圆角处会露方角。规格 W-08 改写。

### #7 Chrome 式浏览标签

**现状**：**没有应用内标签**。侧栏右键「在新标签页中打开」走的是  
`NSWindow.addTabbedWindow`（系统窗口标签，`MainWindowController.swift:2093-2112`），  
且宿主不支持时置灰（`SidebarView.swift:855-862`）。与 Chrome 式标签是两套东西。

**目标模型**

- 每个操作区一条标签条（工具栏上方，高 30pt），标签 = 该面板的一次浏览会话。
- 标签内容：路径 + 前进后退历史 + 视图模式 + 排序/分组 + 标签筛选。
- 交互：`+` 新建、`×` 关闭、拖动排序、**跨左右面板拖动**、双击空白新建、中键关闭。
- 快捷键：⌘T 新建、⌘W 关闭当前标签（最后一个标签时关窗）、⌃Tab / ⌃⇧Tab 切换。
- 右键文件夹 →「在新标签页中打开」接通（替换现有系统标签实现）。
- 首版不持久化（重启回到上次路径）；不做固定/预览/分组。

**实现要点**

- `PaneState` 已自带 `history/historyIndex/viewMode/sort/tagFilter`（`PaneState.swift:49-50`），  
  一个标签就是一份 `PaneState` 快照，不需要多套 ViewModel。
- 新增 `PaneTabsStore`（纯函数：新建/关闭/移动/激活索引调整）→ 可单测；  
  `PaneViewModel` 增加 `captureSession()` / `restore(_:)`，切换时取消进行中的目录列举  
  （沿用现有 generation 机制）。
- 新增 `PaneTabStripView` / `PaneTabItemView`；拖拽用自定义 pasteboard 类型，  
  跨 strip 接收后把 session 移交给对侧 `PaneTabsStore`。
- **与系统窗口标签互斥**：`window.tabbingMode = .disallowed`，删除 `addTabbedWindow` 分支。
- 布局影响：操作区顶部 72 → 102pt，最小窗口高度 700 → 可能 720，需重算 W-07。

**风险**：这是 7 条里唯一需要独立设计稿与 4 个可交付子步的功能；跨面板拖拽 + 异步列举取消  
是最容易出竞态的地方，必须有 `PaneTabsStore` 单测与手工拖拽矩阵（左→右、右→左、排序、拖到空白）。
