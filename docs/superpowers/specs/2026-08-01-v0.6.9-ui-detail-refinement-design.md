## 1. 侧边栏收藏夹间距与对齐

### 问题
- "我的收藏"标题与收藏夹文件夹列表之间间距过大（12pt），与"标签"区（4pt）不一致
- 收藏夹文件夹图标最左边缘比"我的收藏"标题文字最左边缘更靠右（有缩进）

### 方案

**1.1 间距修复**
- 文件：`SidebarView.swift`
- 将 `favoritesOutlineView.topAnchor` 到 `favoritesTitleLabel.bottomAnchor` 的 constraint constant 从 `12` 改为 `4`

**1.2 对齐修复**
- `favoritesOutlineView.leadingAnchor` 保持 12pt（与标题一致，已正确）
- 缩进来自 NSOutlineView 内部 cell 的默认偏移，需在 `FFFNoDisclosureOutlineView` 中重写 `frameOfCell(atColumn:row:)` 去除额外偏移
- 确保 `indentationPerLevel = 0`（已有）并检查 `intercellSpacing` 设为 zero
- 使文件夹图标最左边缘与"我的收藏"标题文字最左边缘（leading 12pt）对齐

### 验收标准
- "我的收藏"标题与文件夹列表间距 = 4pt（与标签区一致）
- 收藏夹文件夹图标最左边缘 = "我的收藏"标题文字最左边缘

## 2. 操作区圆角、边框、背景覆盖与分割线

### 问题
- 操作区白色背景（夜间黑色）未正确覆盖到顶部工具栏区域（导航栏+搜索框+路径栏）
- 圆角需从标准圆角改为超椭圆（squircle）曲线
- 需增加 1px 边框
- 需移除侧边栏与操作区之间、两个操作区之间的分割线
- 拖动调整宽度时不再显示操作区蓝色边框，改为从鼠标位置向两边渐变的亮线

### 方案

**2.1 背景覆盖修复**
- 文件：`MainWindowController.swift`
- 检查 `createPaneContainer(side:)` 中 `toolbar.topAnchor` 约束，确保工具栏在 container 顶部且背景色覆盖
- 确认 `container.layer?.masksToBounds = true` 裁剪范围包含工具栏

**2.2 超椭圆圆角（Squircle）**
- 新建文件：`UI/SquircleView.swift`
- 创建 `SquircleView` 工具类（`NSView` 子类），重写 `layout()` 时用 `CGPath` 绘制超椭圆路径
- 超椭圆算法：使用 n 次方曲线公式 `|x/a|^n + |y/b|^n = 1`（n ≈ 4-5），生成平滑路径点，用 `CGPath.addLines` 连接
- 通过 `CAShapeLayer` mask 实现超椭圆圆角，而非 `cornerRadius`
- 应用到所有圆角位置（按位置调整半径）：
  | 位置 | 半径 |
  |------|------|
  | 操作区容器 | 16pt |
  | 详情栏浮层 | 12pt |
  | 搜索框组件 | 8pt |
  | 标签药丸 | 高度的一半（胶囊形） |
  | 按钮/小组件 | 4-8pt |

**2.3 1px 边框**
- 文件：`MainWindowController.swift`
- `container.layer?.borderWidth = 1`
- 日间模式：`NSColor.separatorColor`（约 `#E5E5E5`）
- 夜间模式：`NSColor(srgbRed: 0.227, green: 0.227, blue: 0.227, alpha: 1.0)`（约 `#3A3A3A`）
- 在 `refreshOperationAreaBackgrounds()` 中同步刷新边框颜色

**2.4 移除分割线**
- 文件：`MainWindowController.swift`
- NSSplitView 无"无分割线"样式，需自定义 NSSplitView 子类重写 `dividerThickness` 返回 0
- `mainSplitView` 和 `paneSplitView`（FFSplitView）均使用自定义子类，divider 厚度设为 0
- 同时设置 `dividerStyle = .thin`（仍需保留以支持拖拽功能，只是视觉宽度为 0）
- 侧边栏与操作区之间、两个操作区之间均无可见分割线

**2.5 拖动渐变亮线**
- 文件：`MainWindowController.swift`（FFSplitView 内部类）
- 当 `isHoveringDivider` 为 true 时：
  - 移除操作区蓝色边框逻辑（`borderWidth = 1` → 删除）
  - 在 divider 位置绘制垂直渐变线：
    - `CAGradientLayer`，`colors = [NSColor.clear, NSColor.controlAccentColor, NSColor.clear]`
    - `locations = [0, 0.5, 1]`（中心最亮，向两端渐变透明）
    - `startPoint = (0.5, 0)`，`endPoint = (0.5, 1)`
    - 宽度 2pt，高度 = splitView 全高
  - 鼠标移出时移除渐变线

### 验收标准
- 操作区圆角白色背景（夜间黑色）完整覆盖工具栏+路径栏+搜索框+文件列表
- 所有圆角为超椭圆曲线，操作区半径 16pt
- 操作区有 1px 边框（日间浅灰/夜间深灰）
- 侧边栏与操作区之间、两个操作区之间无分割线
- 拖动分隔条时仅显示从鼠标位置向上下渐变的亮线，无操作区蓝色边框

## 3. 详情栏浮动

### 问题
- 详情栏在操作区容器内部底部，文件列表因详情栏展开而缩短

### 方案

- 文件：`MainWindowController.swift`、`ExpandableDetailsBar.swift`
- 将 `ExpandableDetailsBar` 从 `container` 子视图改为添加到 `makeCardWrapper`（操作区圆角卡片包裹层）上
- 文件列表（`listView`/`gridView`）的 `bottomAnchor` 改为锚定 `container.bottomAnchor`（不再锚定 `detailsBar.topAnchor`），列表始终占满操作区全高
- 详情栏使用液态玻璃效果（`FFGlassView(level: .panel)`），浮在文件列表上方
- 详情栏定位约束：
  - `bottomAnchor` = `container.bottomAnchor - 8pt`（底部留 8pt 边距）
  - `leadingAnchor` = `container.leadingAnchor + 8pt`
  - `trailingAnchor` = `container.trailingAnchor - 8pt`
- 展开时增加阴影强化浮动层次：
  - `layer.shadowOpacity = 0.15`
  - `layer.shadowRadius = 8`
  - `layer.shadowOffset = CGSize(width: 0, height: -2)`

### 验收标准
- 文件列表始终占满操作区全高，不因详情栏展开而缩短
- 详情栏以液态玻璃浮层形式悬浮在文件列表上方

## 4. 文件名双行布局

### 问题
- 列表视图文件名单行，标签药丸在右侧横向排列
- 网格视图不显示标签

### 方案

**4.1 列表视图（FileListView.swift）**
- 文件名列 cell 改为双行布局：
  - 上方：文件名 `textField`，约束改为 `topAnchor` 对齐（有标签时）或 `centerYAnchor` 对齐（无标签时）
  - 下方：标签药丸容器，`topAnchor` 锚定 `textField.bottomAnchor + 2pt`
  - 药丸横向排列，`leadingAnchor` 对齐文件名 `leadingAnchor`
- 无标签时：隐藏药丸容器，文件名垂直居中（单行高度）
- 有标签时：文件名顶部对齐，药丸在下方（行高自适应增加）
- 需要实现 `tableView(_:heightOfRow:)` 动态行高：有标签行高 = 单行行高 + 药丸行高(20pt) + 间距(2pt)

**4.2 网格视图（FileGridView.swift）**
- 在 `nameLabel` 下方添加标签药丸容器
- 药丸横向排列居中，`topAnchor` 锚定 `nameLabel.bottomAnchor + 2pt`
- 无标签时药丸容器隐藏，item 高度不变
- 有标签时 item 高度自适应增加（药丸行高约 20pt + 间距 2pt）
- 复用 `FileListView` 中的 `makeTagPill` 逻辑（抽取为共享方法或工具类）

### 验收标准
- 列表视图：有标签文件显示双行（上文件名、下标签药丸），无标签文件单行
- 网格视图：有标签文件在文件名下方显示标签药丸，无标签文件不显示
- 标签药丸样式与侧边栏一致（胶囊形、浅色底、圆点+文字）

## 6. QuickLook 预览修复

### 问题
- 按空格键（或点击预览）时 QuickLook 完全无反应，预览面板不弹出

### 根因分析
- 文件：`QuickLookPreviewView.swift`
- `QuickLookPreviewPanel`（NSObject 子类）实现了 `QLPreviewPanelDataSource` 和 `QLPreviewPanelDelegate`，但**未进入 responder chain**
- `QLPreviewPanel` 没有 `controller` 属性（`currentController` 为只读），它通过 **responder chain 自动查找** controller
- `QLPreviewPanelController` 是 NSObject category（informal protocol），非 Swift 正式协议，包含 `acceptsPreviewPanelControl`、`beginPreviewPanelControl`、`endPreviewPanelControl` 三个方法
- `QuickLookPreviewPanel` 作为 NSObject 无法插入 responder chain（需 NSResponder 子类）
- 当前代码直接调用 `panel.makeKeyAndOrderFront(nil)` 但 panel 找不到 controller，导致面板无法显示

### 方案

- 文件：`QuickLookPreviewView.swift`
- `QuickLookPreviewPanel` 基类从 `NSObject` 改为 `NSResponder`，使其可插入 responder chain
- 实现 `QLPreviewPanelController` informal protocol 方法（使用 `override` 关键字）：
  - `acceptsPreviewPanelControl(_:)` -> `true`
  - `beginPreviewPanelControl(_:)` -> 设置 dataSource 和 delegate
  - `endPreviewPanelControl(_:)` -> 清理 dataSource 和 delegate
- 在 `togglePreview` 方法中：
  1. 调用 `insertIntoResponderChain()` 将 self 插入 key window 的 responder chain
  2. 调用 `panel.updateController()` 强制面板重新搜索 responder chain
  3. 设置 dataSource、delegate、currentPreviewItemIndex
  4. `panel.makeKeyAndOrderFront(nil)` 显示面板
- 关闭时调用 `removeFromResponderChain()` 恢复原 responder chain

### 验收标准
- 选中文件后按空格键弹出 QuickLook 预览面板
- 方向键可切换预览的文件
- Esc 键关闭预览面板
- 再次按空格键可切换显示/隐藏

## 风险与注意事项

1. **超椭圆圆角性能**：`CAShapeLayer` mask 比 `cornerRadius` 略有性能开销，需确保只在静态视图使用，不在高频刷新的 cell 中使用
2. **动态行高兼容**：列表视图从固定行高改为动态行高，需确保分组 header、选中高亮、拖拽等交互不受影响
3. **详情栏浮层遮挡**：浮层覆盖文件列表底部，需确保用户能滚动查看被遮挡的文件（列表可滚动到浮层下方）
4. **工具面板覆盖层级**：`ToolOverlayView` 需正确添加到操作区 container 上方，z-order 高于文件列表但低于窗口级元素
5. **分割线移除后的拖拽**：移除分割线后仍需保留拖拽调整宽度的功能，只是视觉上不可见，拖拽时显示渐变亮线
