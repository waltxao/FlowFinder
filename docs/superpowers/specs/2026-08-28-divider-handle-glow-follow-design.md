# 分隔线手柄「渐变跟随 + 拖动完全跟随」设计

> **日期：** 2026-08-28
> **状态：** 设计已获用户逐项确认（澄清 3 问 + 方案选择 + 设计确认）
> **范围：** 左右双操作区分隔线（`FFSplitView`）的悬停手柄渐变效果与拖动跟随
> **关联文件：** `FlowFinderNative/FlowFinderNative/UI/MainWindowController.swift`（`FFSplitView`，约 13-158 行）

---

## 1. 背景与问题

两个操作区（左右文件面板）之间的分隔区域为 `FFSplitView`（NSSplitView 子类）：

- `dividerThickness = 0`（无可见分割线），鼠标进入分隔 X 位置 ±6pt 热区时显示 2pt 宽、全高的渐变亮线（CAGradientLayer：clear → accent → clear，`locations` 固定 `[0, 0.5, 1]`）。
- 拖动为手动实现（dividerThickness=0 时 NSSplitView 内置拖拽失效）：`mouseDown` 在热区内记录起点，`mouseDragged` 按增量调 `setPosition`，亮线回读 `subviews[0].frame.maxX` 定位。

用户反馈的两个问题（已确认症状）：

1. **最亮点固定在正中间**：渐变 `locations` 固定为 `[0, 0.5, 1]`，最亮点始终在窗口高度正中，不随鼠标上下位置移动。用户确认症状：「亮点位置不动」。
2. **拖动不完美跟随**：CAGradientLayer 的 frame 更新默认带约 0.25s 隐式动画，频繁更新表现为亮线「追着鼠标跑」的迟滞感。用户确认症状：「亮线反应慢半拍」。次要因素：亮线位置回读布局结果（可能滞后一拍）；拖动为相对位移（保留按下时鼠标与分隔线的初始偏差，用户未直接反馈此项，但按「完全跟随」目标一并修复）。

## 2. 需求（已与用户逐项澄清）

| 项 | 结论 |
|----|------|
| 悬停亮点 | 最亮点跟随鼠标 Y 实时移动；上下各约 120pt 渐隐至透明（总高约 240pt），按固定像素换算、不随窗口高度拉伸。**2026-08-29 验收调优**：原 60pt 偏小，扩至 120pt；亮点颜色由纯强调色改为向白色提亮 50%（线宽保持 2pt）；渐变端点由 clear（透明黑，插值掺黑成暗色带）改为峰值色的 0 透明度版本（插值只变透明度不变色相） |
| 边缘行为 | 鼠标贴近窗口顶/底时亮点贴边，光在窗口边界自然截断 |
| 拖动对齐 | 按下瞬间分隔线与亮线立刻对齐到鼠标正下方（绝对跟随；跳动 ≤ 热区半径 6pt，肉眼几乎不可察觉） |
| 拖动跟随 | 全程与鼠标 X 1:1 同步、无迟滞；最亮点同时跟随鼠标 Y |
| 最小宽度 | 保留现有保护：每侧面板 ≥450pt（delegate `constrainMin/MaxCoordinate`），拖到极限线停住属正常行为 |
| 渐隐范围 | 用户选定「中（约 120 像素总高）」，否决「短 60px」与「全高渐隐」 |
| 实现方案 | 用户选定方案 A「精准改造现有亮线」，否决方案 B「自定义绘制光斑」与方案 C「实体分隔条交给系统拖动」 |

## 3. 设计

### 3.1 改动位置

仅 `FFSplitView` 类内部（约 145 行范围），不碰整体布局结构、不碰卡片边距、不碰侧边栏分隔线（`FFNoDividerSplitView`）。

### 3.2 迟滞修复（根因）

- 亮线 `frame` 与渐变 `locations` 的**所有**更新统一包裹 `CATransaction.begin()` / `setDisableActions(true)` / `commit()`，消除 Core Animation 隐式动画（慢半拍主因）。
- 亮线 X 直接使用计算值：
  - 悬停时：`dividerX = subviews[0].frame.maxX`（静止状态，回读无碍）；
  - 拖动时：直接用刚计算出的 `clampedWidth`（即 `setPosition` 传入的值），**不回读布局结果**，保证零延迟。

### 3.3 亮点跟随鼠标 Y

- `mouseMoved` 与 `mouseDragged` 两条事件路径都计算鼠标在 splitView bounds 内的 Y 并更新渐变。
- 渐变 `locations` 动态设为 `[f - r, f, f + r]`，其中 `f` 为鼠标 Y 归一化（0~1），`r = 120 / bounds.height`（固定 120pt 渐隐半径换算成比例，2026-08-29 由 60 调大），两端 clamp 到 `[0, 1]` 并保持有序。
- 坐标系注意：NSView 原点在左上、y 向下；CALayer/CAGradientLayer 单位坐标 y 向上（location 0 对应 startPoint 端）。方向以唯一验收事实为准——「鼠标越靠上、亮点越靠上」；若实现后方向颠倒，将 Y 归一化取反（`1 - f`）即可。
- 亮点贴边：`f` 直接 clamp 到 `[0, 1]`，不强制亮点内缩——贴近窗口顶/底时亮点贴边、光在窗口内被自然截断（符合需求）。

### 3.4 按下对齐（绝对拖拽）

- 采用**绝对跟随模型**：拖动全程（含按下瞬间）分隔线目标位置一律取当前鼠标 X，即 `newWidth = clamp(point.x)`，不再使用「起点 + 增量」的相对位移模型，也就无需 `dragStartX` / `dragStartWidth` 记账字段。
  - `mouseDown` 命中热区（±6pt）时：`setPosition(clamp(point.x), ofDividerAt: 0)`——分隔线立即对齐鼠标正下方（跳动 ≤6pt）；
  - `mouseDragged` 中：同样 `setPosition(clamp(point.x))`，使 dividerX ≡ mouseX（极限范围内严格成立）；
  - 极限边缘场景（分隔线已贴死限制、鼠标在热区外沿按下）下，绝对模型仍保证「能动的范围内严格贴鼠标」，不会像相对模型那样把按下的偏移量带入全程。
- clamp 口径统一：现有手动 clamp（min 200）与 delegate 约束（min 450）不一致，实现时手动 clamp 对齐 450（min 450、max `bounds.width - 450`），避免两处口径不同造成的理解歧义。实际生效约束仍以 delegate 为准。

### 3.5 事件与状态

| 事件 | 行为 |
|------|------|
| `mouseMoved`（悬停） | 悬停判定不变（±6pt）；显示亮线并更新亮点 locations（鼠标 Y） |
| `mouseDown`（热区内） | 对齐鼠标 → 显示亮线 → 进入拖拽；亮点按按下位置设置 |
| `mouseDragged`（拖拽中） | 同步更新：divider 位置、亮线 X（= 计算值）、亮点 locations（鼠标 Y）；全部禁隐式动画 |
| `mouseUp` | 行为不变：亮线留在最终分隔位置；按鼠标是否仍在 ±6pt 决定悬停态 |
| `mouseExited` | 行为不变：隐藏亮线 |

光标（`NSCursor.resizeLeftRight`）逻辑不变。

## 4. 验收标准

1. 悬停：鼠标在热区内上下移动，最亮点实时跟随鼠标高度，上下各约 60pt 渐隐至看不见。
2. 拖动：从按下瞬间起，分隔线与亮线与鼠标 X 完全同步，无任何迟滞感；亮点同时跟随鼠标 Y。
3. 拖到极限（任一侧 450pt）线停住，鼠标继续移动不越界、松手后行为正常。
4. 悬停出现/离开消失行为与现状一致；侧边栏分隔线、布局结构、宽度记忆均不受影响。
5. 测试基线全绿：`make rust-test`（200 passed）+ `make swift-test`（73 passed）。
6. 用户实测新 .app 通过。

## 5. 不做（Out of Scope）

- 侧边栏与操作区分隔线（`FFNoDividerSplitView`）的任何效果。
- 自定义逐帧绘制光斑（方案 B）。
- 实体分隔条改造（方案 C）。
- 亮线出现/消失的淡入淡出动画。
- 拖动把手的其他视觉装饰（如三点纹）。

## 6. 风险与回退

- 改动集中在单文件单类，出问题可直接回退该文件改动。
- 唯一布局相关风险点为「按下瞬间对齐」触发的一次 `setPosition`：跳动 ≤6pt 且受 delegate 约束收口，不会引发布局约束冲突（不动任何约束常量）。
