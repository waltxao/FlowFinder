# 详情栏重设计「可调高度 + 三模块可调宽 + 流动填充」设计

> **日期：** 2026-08-29
> **状态：** 设计已获用户逐项确认（澄清 3 问含可视化示意图选择 + 方案选择 + 设计确认）
> **范围：** 每面板底部详情栏（`ExpandableDetailsBar`）展开态布局的交互重设计
> **关联文件：** `FlowFinderNative/FlowFinderNative/UI/ExpandableDetailsBar.swift`（约 1733 行）、新增纯数学核心（`FFCommon.swift`）、测试（`FlowFinderNativeTests.swift`）

---

## 1. 背景与现状

详情栏是浮在每个面板底部的圆角卡片（浮层设计：文件列表延伸至底部，卡片覆盖其上）：

- 高度固定两档：收起 54pt / 展开 210pt 基准 + 类型专属信息行数扩展（`computedExpandedHeight()` 按内容自动加高），左上角箭头按钮切换。
- 展开态内容行 = 横向 NSStackView：大图标（固定尺寸）+ 列1（名称/种类/大小/位置/创建日期/修改日期 + 类型专属信息）+ 列2（标签/文件说明/来源）。
- 底部状态栏 18pt（项目数 + 磁盘可用空间）。
- 多选汇总（v0.7.4）与单选同布局：图标堆叠 + 数量/总大小/类型/标签药丸两列。

用户反馈的问题：高度不可调、图标大小不可调、两列宽度不可调、信息项排列不随高度自适应。

## 2. 需求（已与用户逐项澄清）

| 项 | 结论 |
|----|------|
| 高度调整方式 | **箭头按钮保留**（收起/展开快捷切换），新增**按住上边缘上下拖动**调到任意高度 |
| 自动排列语义 | 用户在可视化示意图中选定 **A · 流动填充**：项按固定顺序排列，栏变矮时列1装不下的项自动流到列2，变高时流回；两列都装不下时剩余项暂时隐藏 |
| 图标大小调整 | **拖图标区右边界 = 调图标大小**（图标在图标区内居中、跟随宽度缩放）——「图标大小可调」与「图标区宽度可调」合并为同一动作 |
| 三模块宽度 | 图标区\|列1、列1\|列2 两条分界线均可拖动，样式沿用双栏分隔线手柄（细分隔线 + 悬停亮起 + 拖拽光标） |
| 记忆与同步 | 展开高度、两条分界线位置自动保存（UserDefaults），重启恢复；**左右两个面板共用同一套**尺寸（拖左栏右栏同步） |
| 实现方案 | 用户选定方案 A「在现有卡片内精准改造」；否决方案 B（系统 NSSplitView 承载模块，样式融合难+布局约束风险史）与方案 C（完全自绘） |

## 3. 设计

### 3.1 改动位置与文件

- **不新增文件**（pbxproj 脆弱，沿用项目既定约束）：
  - 纯数学核心 `FFDetailsFlowLayout` 追加到 `FFCommon.swift`（与 `FFDividerGlowMath`、`FFMotion` 同模式）；
  - 单元测试追加到 `FlowFinderNativeTests.swift`；
  - 布局改造集中在 `ExpandableDetailsBar.swift`。
- 不触碰：视觉风格（字体/颜色/圆角/状态栏样式）、多选汇总内容、浮层关系、pbxproj。

### 3.2 高度拖拽

- 详情栏顶部边缘设 6pt 拖拽热区（tracking area），悬停显示 `resizeUpDown` 光标；按住拖动实时改 `heightConstraint.constant`。
- 展开态高度 clamp：**最小 100pt**（图标 + 至少两行信息 + 状态栏），**最大 = 所在面板高度 − 120pt**（保证文件列表始终露出一截）；拖动中实时 clamp。
- `computedExpandedHeight()`（按内容自动加高）**退役**：用户拖出的高度成为权威值，装不下的内容由流动填充算法隐藏（替代原来的自动加高）。
- 箭头按钮行为不变：收起 = 54pt，展开 = 记忆的展开高度（首次使用默认 210pt）。
- 高度记忆 key：`FFDetailsBarExpandedHeight`（左右面板共用）。

### 3.3 两条内部拖拽线

- 图标区与列1、列1 与列2 之间各放一条 1pt 分隔线（`CAGradientLayer` 亮线，视觉复用 `FFSplitView` 手柄模式：悬停 ±6pt 热区亮起、`resizeLeftRight` 光标、拖动实时跟随、禁隐式动画）。
- 拖动 clamp：图标区宽度 **[32, 内容行总宽 − 240]**（列1、列2 各至少保留 120pt）；列1 宽度最小 120pt；列2 兜底剩余宽度（同样 ≥120pt，窗口过窄时整体按最小值收口）。
- 图标边长 = min(图标区宽度 − 16, 内容区高度 − 16)，下限 32pt；图标居中。
- 记忆 key：`FFDetailsBarIconWidth`、`FFDetailsBarColumn1Width`（共用）。

### 3.4 流动填充纯函数（FFDetailsFlowLayout）

- 项的固定顺序：**名称 → 种类 → 大小 → 位置 → 创建日期 → 修改日期 → 类型专属信息行… → 标签 → 说明 → 来源**（高度充裕时列1 恰好装到类型专属为止、列2 装后三项——与现状分组一致）。
- 核心函数（纯函数，可单测，签名固定）：
  - `flowSplit(itemHeights: [CGFloat], availableHeight: CGFloat) -> Int`：返回列1 应装的项数（按顺序累计高度，装不下的起流入列2）；
  - `visibleItemCount(itemHeights: [CGFloat], availableHeight: CGFloat) -> Int`：两列合计可见项数（列2 也装不下的项隐藏）。
- 多选汇总行（数量/总大小/类型/标签药丸）同样走流动填充（各行高度不同：药丸行按实际高度计）。
- 触发重排的时机：高度拖拽中、分界线拖拽中（列宽只影响文字截断不影响分配，但图标大小变化会改变内容区高度）、选中变化刷新后、窗口/面板尺寸变化后。

### 3.5 交互细节

- 拖上边缘与拖两条内部分界线共用同一套手写拖拽机制（`mouseDown` 记录起点 → `mouseDragged` 实时 clamp 更新 → `mouseUp` 落盘记忆），三处热区互不重叠（上边缘热区优先级最高）。
- 拖动过程中文件列表不需让位（浮层覆盖设计，滚动仍可达全部文件）。
- 状态栏始终可见（18pt 固定于卡片底部，不参与拖拽隐藏）。
- 收起态（54pt）不显示拖拽热区与内部分界线（维持现状简洁）。

## 4. 验收标准

1. 按住详情栏上边缘上下拖动，高度实时平滑变化；松手后重启应用高度恢复。
2. 箭头按钮：收起/展开行为与现在一致，展开高度 = 拖出并记忆的高度。
3. 拖动图标区分界线：图标实时缩放、居中，不超过栏高；列1/列2 分界线可拖，文字极限处收口不挤压。
4. 栏拖矮：列1 装不下的项自动出现在列2；两列都装不下时剩余项隐藏；拖高时项流回，最多项全部可见。
5. 左右面板尺寸同步：拖左栏高度/分界线，右栏跟随；重启后一致。
6. 多选汇总同布局适用；状态栏始终可见。
7. 现有测试基线全绿（Rust 200 / Swift 85 + 新增流动填充等单测），用户实测通过。

## 5. 不做（Out of Scope）

- 视觉风格改动（字体、颜色、圆角、状态栏样式）。
- 第三列、列内容自定义/拖拽排序。
- 收起态的任何改动（除箭头逻辑不变外）。
- 文件列表与卡片浮层关系的改动。

## 6. 风险与回退

- 改动集中在单文件 + 纯函数，出问题可回退对应提交。
- 主要风险点：①手写拖拽与既有 tracking area/动画的相互作用（沿用 FFSplitView 已验证模式）；②`computedExpandedHeight()` 退役后旧有「问题 9 截断」回归——由流动填充的隐藏语义替代，需用户实测确认观感；③pbxproj 不触碰，无工程文件风险。
