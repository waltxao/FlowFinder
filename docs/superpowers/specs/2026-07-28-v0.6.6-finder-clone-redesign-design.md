# v0.6.6 仿访达完整重设计

> **日期：** 2026-07-28
> **版本：** v0.6.6（计划）
> **前置版本：** v0.6.5 (650)
> **状态：** 待用户审阅

---

## 1. 背景

v0.6.5 发布后用户验收反馈 20 个问题，其中 7 个是 v0.6.5 修复错误或遗漏（F4 图标方向错、F7 选中背景错、F8 grid 未覆盖等），其余为接线 bug、功能缺失、视觉差距。用户明确要求"完全克隆访达视觉"。

## 2. 方向决策

| 决策点 | 选择 |
|--------|------|
| 整体视觉目标 | 完全克隆访达视觉（材质/间距/选中色/夜间模式） |
| title 栏 | 移除，红绿灯浮在侧边栏上方（titlebarAppearsTransparent + fullSizeContentView） |
| 收藏夹图标 | 彩色真实图标（NSWorkspace.shared.icon(forFile:)，修正 F4 的蓝色模板错误） |
| 收藏夹布局 | 不折叠、左对齐、标签永远在最后一个文件夹下方 |
| 标签模块 | 彩色圆点 + 完整标签名垂直排列 |
| 列头 | 访达风格药丸列头（圆角背景、可点击排序）+ 可拖动调整顺序 |
| 升降序 | 移除独立按钮，改为列头点击切换升降序 |
| 分组维度 | 按种类/按日期/按大小，实现分组聚合 + section 渲染 |
| 网格视图 | 完全照搬访达（系统图标/缩略图 + 实心蓝选中） |
| 设备区域 | 浮动在窗口左下角独立区域，展开显示所有设备不需滚动 |
| 文件夹右键菜单 | 新增"在另一侧打开"（仅文件夹，导航另一侧面板） |

## 3. 整体架构策略

六层分阶段推进，先修窗口架构根基，再逐层向上：

```
第一层：窗口架构重建（根基）
  └── 问题9（移除title栏）+ 问题14（选中渲染，修正F7错误）+ 问题18（设备浮动）+ 问题15/16辅助（window.delegate）
       │
       v
第二层：侧边栏重构（仿访达）
  └── 问题1（收藏夹彩色图标+不折叠）+ 问题2（标签圆点+文字垂直）
       │
       v
第三层：文件列表重构（仿访达）
  └── 问题4（列宽自动）+ 问题5（药丸列头+可拖动）+ 问题12（列头升降序）+ 问题6（分组section）
       │
       v
第四层：网格视图重构（仿访达）
  └── 问题7（网格照搬访达）+ 问题10（缩略图修复，含grid复用）
       │
       v
第五层：功能接线修复
  └── 问题3（设置/工具窗口）+ 问题11（搜索）+ 问题13（在另一侧打开）+ 问题15/16（右键菜单）+ 问题17（查重/重命名）
       │
       v
第六层：视觉打磨
  └── 问题19（整体视觉克隆访达）+ 问题20（夜间模式克隆访达）
```

**设计原则：**
- 纯 UI 层修改，不动 Rust Core
- 每个修复点标注"修正 v0.6.5 错误"或"新增"
- 每层完成后构建验证
- 所有 UI 文案和代码注释使用简体中文
- 主题切换保持 light/dark 二态

## 4. 第一层：窗口架构重建（问题9/14/15-辅助/18）

### 4.1 问题9 - 移除 title 栏，红绿灯浮在侧边栏上方

**修改文件：** `MainWindowController.swift`

- 窗口 `styleMask` 添加 `.fullSizeContentView`
- 设置 `titlebarAppearsTransparent = true`，`titleVisibility = .hidden`
- 移除当前的 28pt titlebarView 占位视图
- 侧边栏 `topAnchor` 改为直接贴 `window.contentView.topAnchor`
- 侧边栏顶部留出 ~28pt 安全区给红绿灯，应用图标下移到红绿灯下方

### 4.2 问题14 - 单击选中渲染修复（修正 F7 错误）

**修改文件：** `FileListView.swift`

**关键修复：** `FileListView.swift:202` 将 `tableView.backgroundColor = NSColor.textBackgroundColor.withAlphaComponent(0.6)` **改回 `.clear`**

- F7 的 0.6 alpha 背景是遮挡 `NSTableRowView.drawSelection` 的元凶
- 选中色由 NSVisualEffectView 玻璃材质衬托，无需 tableView 自身底色
- 保留 F7 的 OpaqueContainerView、makeKey、appearance 同步（这些正确）
- cellView.layer.backgroundColor 保持 `.clear`
- 同步修复 FileGridView 的选中样式（问题7 第四层处理）

### 4.3 问题15/16 辅助 - 窗口 key 状态修复

**修改文件：** `MainWindowController.swift`

- 设置 `window?.delegate = self`（当前未设置，导致 windowDidBecomeKey 等回调不触发）
- 影响右键菜单弹出、鼠标事件接收，是问题15/16 的潜在根因

### 4.4 问题18 - 设备区域浮动在窗口左下角独立区域

**修改文件：** `SidebarView.swift`、`MainWindowController.swift`

- 设备区域从侧边栏内部移出，改为 MainWindowController 中独立浮层
- 浮层定位：贴窗口左下角，`bottomAnchor = window.contentView.bottomAnchor`
- 展开时 `heightAnchor` 根据设备数量自适应（不需滚动条）
- 折叠时仅显示汇总头部
- 与侧边栏收藏夹/标签模块视觉分离

## 5. 第二层：侧边栏重构（问题1/2）

### 5.1 问题1 - 收藏夹仿访达（修正 F4 错误）

**修改文件：** `SidebarView.swift`

- **图标改回彩色真实图标：** 移除 F4 的蓝色模板 SF Symbols，改回 `NSWorkspace.shared.icon(forFile: path)`
- **放大图标尺寸：** 从 16pt 改为 18-20pt（对齐访达侧边栏图标尺寸）
- **不折叠展示：** 收藏夹项目直接列出，无折叠箭头，默认全部展开
- **左对齐：** `indentationPerLevel = 0`（保留），图标贴左边缘
- **标签模块永远在最后一个文件夹下方：** 侧边栏纵向 stack：收藏夹 section（动态高度）-> 标签 section（紧跟下方）
- **选中样式：** sourceList 半透明蓝高亮（保留 F4 的 sourceList 设置）

### 5.2 问题2 - 标签模块重设计

**修改文件：** `SidebarView.swift`（TagFlowView 重构）

- **布局改为垂直排列：** 移除横向 wrap 布局，改为垂直纵向排列（每行一个标签）
- **每个标签：** 彩色圆点（8pt，tag.color）+ 完整标签名文字（13pt）
- **行高：** 28pt（对齐访达侧边栏项目高度）
- **不遮挡标题：** 标签 section header 与标签列表留足间距，header 固定顶部
- **药丸可拉长：** 标签行宽度填满侧边栏，文字完整显示不截断
- 保留拖拽删除、点击筛选等交互

## 6. 第三层：文件列表重构（问题4/5/6/12）

### 6.1 问题4 - 列宽自动调整占满操作区

**修改文件：** `FileListView.swift`

- 四列 `resizingMask` 从仅 `.userResizingMask` 改为 `[.userResizingMask, .autoresizingMask]`
- 设置 `tableView.columnAutoresizingStyle = .lastColumnOnly`（最后一列自动填充剩余宽度）
- 移除"不调用 sizeToFit"的过时注释
- 调整操作区 divider 时，列宽自动响应占满

### 6.2 问题5 - 列头改访达药丸样式 + 可拖动调整顺序

**修改文件：** `FileListView.swift`

- 自定义列头 view（替换默认 NSTableHeaderCell）：圆角背景（controlBackgroundColor）+ 文字 + 排序箭头
- 列头可点击排序
- `tableView.allowsColumnReordering = true`（启用列拖动重排）
- 拖动时显示半透明列头跟随鼠标，松开插入新位置

### 6.3 问题12 - 移除独立升降序按钮，改为列头点击切换

**修改文件：** `PaneToolbar.swift`、`FileListView.swift`

- `PaneToolbar.swift`：移除 `sortDirectionButton`
- 排序方向改为由列头点击控制：第一次点击升序（箭头向上），第二次点击降序（箭头向下）
- 列头显示当前排序状态（箭头图标）

### 6.4 问题6 - 分组功能照搬访达

**修改文件：** `PaneState.swift`、`FileListView.swift`、`FileGridView.swift`

- `PaneState.swift`：新增 `groupedFiles: [(key: String, entries: [FileEntry])]` 计算属性，按 `state.groupBy` 聚合
  - 按种类：文件夹/图片/文档/视频/音频/其他
  - 按日期：今天/昨天/本周/本月/更早
  - 按大小：>1GB / >100MB / >10MB / >1MB / 更小
- `FileListView.swift`：实现 sectioned 渲染
  - 每个 group 一个 section header（显示 group key + 数量，如"图片 (12)"）
  - section header 样式：浅灰背景、小字号、粘性定位
- `FileGridView.swift`：同样实现 sectioned 渲染
- 排序在分组内生效

## 7. 第四层：网格视图重构（问题7/10）

### 7.1 问题7 - 网格视图完全照搬访达

**修改文件：** `FileGridView.swift`

- **选中样式：** 0.15 alpha 改为访达风格实心蓝半透明（`controlAccentColor.withAlphaComponent(0.25)` + 圆角）
- **缩略图/图标：** 系统默认文件夹/文件图标 + QLThumbnailGenerator 真实缩略图
- **布局：** NSCollectionViewGridLayout，item 尺寸仿访达（图标 + 文件名下方 2 行截断）
- **appearance 同步：** FileGridView 增加 `layout()` override + `refreshAppearance()`，MainWindowController 主题监听也调用 grid
- **列数自适应：** 根据操作区宽度自动调整列数

### 7.2 问题10 - 缩略图修复（修正 F8 遗漏 + ThumbnailManager bug）

**修改文件：** `ThumbnailManager.swift`、`FileGridView.swift`

- **ThumbnailManager bug：** `ThumbnailManager.swift:99-102` NSImage.size 用 cgImage 像素尺寸（Retina 翻倍），改为用请求的 point size
- **representationTypes：** `.thumbnail` 改为 `.all`（.thumbnail ⌒ .icon），无缩略图文件类型回退到图标
- **FileGridView 复用校验（F8 遗漏）：** FileGridCollectionViewItem 增加 `currentPath` + `prepareForReuse()` 取消旧请求 + 回调路径校验
- **网格缩略图尺寸：** 从 96pt 调整为匹配 item 图标区域尺寸

## 12. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 列头自定义+分组 section 是 FileListView 大改，可能引入回归 | 每步构建验证，保留旧实现注释便于回滚 |
| 窗口架构调整（titlebarAppearsTransparent）影响布局 | 红绿灯安全区仔细调整，构建后立即验证 |
| 分组 section 渲染与排序/列宽自动调整可能冲突 | 分组内排序，列宽在分组内生效 |
| 缩略图修复涉及 ThumbnailManager 公共 API | 保持 API 不变，仅修内部实现 |
