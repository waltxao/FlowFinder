# V0.8.0 规格：面向普通用户的测试版

> **日期：** 2026-10-17
> **前序：** `2026-10-17-v0.8.0-requirements-audit.md`（需求审查，已确认走「发行工程化优先 + 全面重构」）
> **设计参考：** [zai-org/ZCode](https://github.com/zai-org/ZCode) `DESIGN.md` + `docs/design/workspace-independent-panels.md`
> **性质：** 本文件是 V0.8.0 的**唯一需求与验收基线**，与历史 spec 冲突时以本文件为准

## 1. 产品定义（此前完全缺失）

### 1.1 一句话定位

**FlowFinder 是一个 macOS 上的双栏文件管理器，为需要「同时看两个目录、批量搬文件」的人设计。**

不是访达替代品。访达是单栏、面向所有 Mac 用户；FlowFinder 的价值在双栏 + 键盘全流程 + 批量操作。

### 1.2 目标用户

| 用户 | 场景 | 关键诉求 |
|------|------|----------|
| 主要 | 开发/运维/设计，日常在多个目录间搬运素材与构建产物 | 双栏对照、键盘完成全流程、大目录不卡 |
| 次要 | 刚接触 Mac 的新用户 | 打开就能用，不需要学 |

### 1.3 明确不做（out of scope）

- 不做访达的完整替代（不接管默认文件管理器、不做「打开方式」注册）
- 不做云盘同步、不做版本控制、不做代码编辑器
- 不做 iOS/iPadOS 协同、不做多语言（V0.8.0 仅简体中文）
- 不做插件系统、不做 App Store 上架

### 1.4 与访达的关系

**视觉与交互向 macOS 原生靠拢（用户预期），而信息密度与布局独立设计（产品差异）。** 不追求像素级克隆访达——12 轮克隆迭代已证明这条路投入产出比极低。

## 2. 需求基线：V0.8.0 必须做到什么

### 2.1 用户旅程验收（5 条主线）

测试版必须让陌生用户独立走通以下 5 条路径，全程无需查文档：

| # | 旅程 | 通过标准 |
|---|------|----------|
| J1 | 首次打开 → 看到自己的文件 | 3 步内看到「桌面/文档/下载」的**真实内容**（含权限引导，不是空白） |
| J2 | 双栏搬一个文件 | 左栏选文件 → 拖到右栏 → 文件到位，两栏同步刷新 |
| J3 | 用键盘找并打开一个文件 | ⌘F 搜索 → ↑↓ 选 → Enter 打开，全程不碰鼠标 |
| J4 | 误删后恢复 | 删除 → ⌘Z 恢复，文件回到原位 |
| J5 | 遇到问题时知道怎么办 | 无权限/只读/断线三种情况给出中文人话提示 + 下一步动作 |

### 2.2 功能分级（全保留，但诚实标注）

| 级别 | 功能 | UI 处理 |
|------|------|---------|
| 核心 | 浏览（列表/网格）、双栏、复制/移动/删除/重命名、新建文件夹、搜索、预览、多选、排序/分组、撤销重做、收藏 | 首屏可见，工具栏/右键一级 |
| 增强 | 标签、批量重命名、查重扫描、详情栏 | 首屏可见但不上工具栏；设置页可关 |
| 实验 | SMB 网络存储、任务调度中心 | **入口下沉**到菜单，标注「实验功能」 |
| 改名 | 「AI 自动打标签」→ **「按类型自动打标签」** | 全项目文案替换，README 同步 |

> 诚实性是测试版口碑的底线。规则引擎不能叫 AI。

### 2.3 非功能要求

| 项 | 指标 | 验证方式 |
|----|------|----------|
| 冷启动 | 进程出现 < 1s，窗口可交互 < 2s | 秒表 / Instruments |
| 大目录 | 10,000 项目录滚动不掉帧（≥55fps） | 实测 + Instruments |
| 主线程 | 无 >100ms 同步任务（除首次布局） | Instruments Time Profiler |
| 常驻内存 | < 250 MB（1 万项目录） | Activity Monitor |
| 崩溃 | 5 条主线各跑 3 遍，0 崩溃 | 手工 + 日志 |
| 约束冲突 | 冷启动 + 主线操作，`Unable to simultaneously satisfy constraints` = 0 | 控制台 |

## 3. 设计基线：从 ZCode 移植什么

### 3.1 ZCode 的设计立场（原文要点）

> "calm, dense, and operational rather than decorative"；"Layer primarily through background contrast, borders, and radius before relying on heavy shadows"；"Avoid: oversized marketing-style spacing, playful gradients, bright full-surface brand fills"

这直接否定了当前 FlowFinder 的三条做法：液态玻璃叠层、超椭圆装饰、多重投影。

### 3.2 布局模型：独立面板 + 4px 间隙（核心变更）

ZCode 的工作区不是「一个大容器切几刀」，而是**每块内容是一个独立框**：

```
窗口根背景（background-alt）
┌ 4px 留白 ────────────────────────────────────┐
│ ┌ 侧栏框 ─────┐ 4px ┌ 面板框 ──────┐ 4px ┌ 详情框 ┐ │
│ │ 收藏        │     │ 工具栏        │     │        │ │
│ │ 标签        │     │ 文件列表      │     │        │ │
│ │ 位置        │     │               │     │        │ │
│ └─────────────┘     └───────────────┘     └────────┘ │
└──────────────────────────────────────────────────────┘
```

| 规则 | 值 |
|------|-----|
| 窗口外层留白 | 4pt（四边） |
| 面板间透明间隙 | 4pt，间隙即拖拽热区 |
| 面板框 | 各自 `panelBackground` + 弱边框 + 圆角 |
| 面板圆角 | macOS 26+ = 12pt；更早 = 6pt（与 ZCode 一致） |
| 拖拽指示线 | 2pt 宽，三级文字色 50%，**默认隐藏**，hover/聚焦/拖动时显示，两端按圆角内缩 |
| 关闭某面板 | 不保留间隙，邻接面板铺满 |

**对现有代码的冲击**：`FFSplitView`（dividerThickness=0）+ 浮动详情栏覆盖方案要全部替换为「框架式布局」。这是本次重构的骨架级改动。

### 3.3 设计令牌映射表

ZCode 用 CSS 变量，FlowFinder 用 `NSColor` 动态色。映射如下（新建 `FFDesign` 单一令牌源）：

#### 颜色（浅色 / 深色）

| 令牌 | ZCode 浅色 | ZCode 深色 | AppKit 落地 |
|------|-----------|-----------|-------------|
| `background`（面板底） | `#f8f8f8` | `#161616` | `FFDesign.Color.panelBackground` |
| `backgroundAlt`（窗口根） | `#ececee` | `#0f0f0f` | `FFDesign.Color.windowBackground` |
| `sidebar` | `#f0f0f0` | `#161616` | `FFDesign.Color.sidebarBackground` |
| `header` / `panel` | `#ffffff` | `#202020` | `FFDesign.Color.headerBackground` |
| `card` / `popover` | `#ffffff` | `#2b2b2b` | `FFDesign.Color.cardBackground` |
| `input` | `#ffffff` | `#2b2b2b` | `FFDesign.Color.inputBackground` |
| `border` | `rgba(13,13,13,.10)` | `rgba(255,255,255,.10)` | `FFDesign.Color.border` |
| `borderHover` | `rgba(13,13,13,.15)` | `rgba(255,255,255,.15)` | `FFDesign.Color.borderHover` |
| `hover` | `rgba(13,13,13,.05)` | `rgba(255,255,255,.05)` | `FFDesign.Color.rowHover` |
| `selected` | `rgba(13,13,13,.05)` | `rgba(255,255,255,.10)` | `FFDesign.Color.rowSelected` |
| `fg` | `#262626` | `#f5f5f5` | `FFDesign.Color.textPrimary` |
| `fgSubtle` | fg 60% | 同 | `FFDesign.Color.textSecondary` |
| `fgSubtlest` | fg 40% | 同 | `FFDesign.Color.textTertiary` |
| `brand`（强调） | `#000000` | `#ffffff` | 保留系统强调色（macOS 用户预期） |
| `destructive` | 系统红 | 系统红 | `FFDesign.Color.destructive` |

> 关键取舍：**选中色不再用系统蓝填充**，改为 ZCode 的 `selected`（5~10% 中性遮罩）+ 左侧强调竖条。这更接近现代 macOS（Finder 侧栏、Xcode 导航器）的做法，也避免深色主题下的刺眼蓝块。

#### 字体（适配 macOS，不照抄 14px 基准）

| 令牌 | 值 | 用途 |
|------|-----|------|
| `textXL` | 17 / semibold | 空态主标题、引导页标题 |
| `textLG` | 15 / semibold | 分区标题、详情栏文件名 |
| `textBase` | 13 / regular | 正文、文件名、按钮 |
| `textBaseEmphasis` | 13 / medium | 选中项、当前分区 |
| `textCaption` | 12 / regular | 次要说明、路径 |
| `textSM` | 11 / regular | 辅助信息、tooltip |
| `textXS` | 10 / regular | 徽标、计数、快捷键提示 |
| `mono` | 12 / monospaced | 路径、大小、日期列 |

> 现状是 `caption10/body11/emphasis11sb/title13sb`——整体偏小 2pt，这是「看不清、不精致」的直接来源。本次统一上调到 macOS 标准 13pt 正文。

#### 间距与圆角

| 令牌 | 值 | 用途 |
|------|-----|------|
| `space1..6` | 4 / 8 / 12 / 16 / 20 / 24 | 全部间距只用这六档 |
| `radiusXL` | 12 | 面板框 |
| `radiusLG` | 8 | 卡片、按钮、菜单 |
| `radiusMD` | 6 | 菜单项、输入框 |
| `radiusSM` | 4 | 嵌套容器、药丸内元素 |
| 密度 | 紧凑 24 / 标准 28 / 宽松 34（行高） | 设置页可切 |

> 废除超椭圆（`SquircleView`）。ZCode 的圆角规则是「按嵌套层级递减」，超椭圆既违反该规则，也带来裁剪与性能负担。保留文件（不删代码），但设计系统不再引用。

### 3.4 元素规范（ZCode 组件 → AppKit 控件）

| 元素 | ZCode 规范 | AppKit 落地 |
|------|-----------|-------------|
| 面板框 | `bg-background` + `rounded-xl` + `border-border` | 新建 `FFPanelView`（layer 圆角 + 1px 边框，非 layer 遮罩） |
| 分区标题 | `text-ui-sm` + `fgSubtle` + 左对齐 | 12pt 次级色，与行文本左对齐 |
| 列表行 | hover `bg-hover`，选中 `bg-selected`，12px 内边距 | `FFSidebarRowView` 重写：中性遮罩 + 左侧 2pt 强调条 |
| 标签药丸 | `rounded-full` 仅用于刻意的药丸 | 保留药丸，但内边距改 8×2，字号 10 |
| 工具栏按钮 | ghost 风格，hover `bg-hover`，无边框 | `FFGhostButton`（新） |
| 菜单/弹层 | `rounded-lg` 外壳 + `shadow-md` | `NSMenu` 沿用系统；自绘弹层走 `radiusLG + shadow` |
| 空态 | 居中图标 + 一行说明 + 一个主操作 | `FFEmptyStateView`（新） |
| 分隔线 | `border-border` 1px | 1px，不用阴影 |
| 焦点环 | 保留可见焦点 | `focusRingType = .default`（现状是 `.none`，无障碍缺陷） |

### 3.5 明确废除的视觉做法

| 废除项 | 原因 |
|--------|------|
| 主面板液态玻璃（`FFGlassView` 用于侧栏/操作区/工具栏） | 与「边框分层」冲突，且造成材质打架 |
| 超椭圆圆角 | 违反嵌套层级规则 |
| 多重投影（详情栏既浮层又阴影） | ZCode：普通布局不靠投影 |
| 灰色硬编码（三套灰度并存） | 统一到令牌 |
| 操作区 1px 装饰边框叠加 | 与面板框边框重复 |
| `selectionHighlightStyle` 自绘蓝块 | 改中性遮罩 + 强调条 |

> `FFGlassView` 保留给菜单/弹层/引导页等真正的 overlay，不再用于结构性面板。

## 4. 重构范围

### 4.1 目标目录结构

```
FlowFinderNative/FlowFinderNative/
├── App/                     应用入口、菜单、AppDelegate
├── Core/
│   ├── DesignSystem/        FFDesign（颜色/字体/间距/圆角/图标）+ FFPanelView 等原子组件
│   ├── Components/          FFSidebarRow / FFTagPill / FFToolbarGroup / FFEmptyState / FFErrorPresenter
│   ├── Localization/        FFStrings（全部 UI 文案单一出口）
│   └── Support/             FFLog（#if DEBUG）、FFFormat、FFUserDefaultsKeys
├── Features/
│   ├── Browser/             列表 / 网格 / 排序分组 / 拖拽
│   ├── Sidebar/             收藏 / 标签 / 位置 / 工具行
│   ├── Details/             详情栏
│   ├── Search/              搜索面板
│   ├── Operations/          复制移动删除重命名 / 批量 / 查重 / 冲突
│   ├── Settings/            设置窗口
│   └── Tasks/               任务面板
├── Services/                Bridge 层（CoreBridge / TagBridge / SMBBridge / Theme / Thumbnail）
└── Model/                   PaneState / FileEntry / Tag / VolumeInfo / SidebarItem
```

### 4.2 巨型类拆分方案

| 现状 | 行数 | 拆成 |
|------|------|------|
| `MainWindowController` | 2167 | `MainWindowController`（窗口壳，≤400）+ `FFWorkspaceLayout`（面板框架布局）+ `FFPaneCoordinator`（双栏协调/撤销/剪贴板）+ `FFDevicePanelController` |
| `FileListView` | 2390 | `FileListView`（表格装配，≤600）+ `FFFileRowCell`（行视图）+ `FFListColumns`（列定义/排序/分组）+ `FFListDragController`（拖放） |
| `SidebarView` | 2194 | `SidebarViewController`（≤400）+ `FFSidebarFavoritesSection` + `FFSidebarTagsSection` + `FFSidebarPlacesSection` + `FFSidebarToolRow` |
| `ExpandableDetailsBar` | 2194 | `DetailsBarView`（≤500）+ `FFDetailsInfoSection` + `FFDetailsTagsSection` + `FFDetailsPreviewSection` |

**拆分纪律**：只搬代码不改行为；每拆一个跑一次 `make swift-test`；拆完行为必须与拆前逐像素一致（截图对比）。

### 4.3 工程债清理

| 项 | 处理 |
|----|------|
| 96 条编译警告 | 清零。selector 字符串化改 `#selector`，废弃 API 替换 |
| 113 处调试日志 | 全部包进 `#if DEBUG`；Release 不留 |
| 878 处硬编码文案 | 收口到 `FFStrings`。V0.8.0 不做多语言，但要有单一出口 |
| ≥16 处死代码 | 按 `代码审查报告.md` 清单逐条删除或接线 |
| 版本号三处不一致 | 单一真源：`version.env` → 构建脚本注入 → 工程/Info.plist/DMG 全部跟随 |

| 阶段 | 内容 | 产出 | 预估 |

## 7. 风险与回滚

| 风险 | 影响 | 对策 |
|------|------|------|
| 设计换血后用户不认 | 高 | P2 完成后立即交付实测，不等到 P5 |
| 巨型类拆分引入回归 | 高 | 拆分只搬不改；每拆一个跑全量测试；保留拆分前 commit 可回退 |
| 878 处文案收口工作量大且易错 | 中 | 分批做（按 Feature 目录），每批编译验证 |
| Release 构建仍不稳定 | 中 | 关 LTO 已实测通过；若仍有问题，先出 Debug 包不阻塞其他阶段 |
| 范围蔓延 | 高 | 本文件为唯一基线，新增需求进 V0.9 |

**分支策略**：`feat/v0.8.0-rebuild` 独立分支，P0-P5 全部完成后一次性合并 main，避免中途污染。
