# v0.6.5 仿访达 UI 重构设计

> **日期：** 2026-07-27
> **版本：** v0.6.5（计划）
> **前置版本：** v0.6.4 (640)
> **作者：** ZCode + Walt
> **状态：** 待用户审阅

---

## 1. 背景

v0.6.4 发布后用户验收反馈界面问题严重，明确提出的 8 个问题如下：

1. 收藏夹没有按访达设计标准
2. 标签的药丸没有正确显示
3. 右侧双操作区都没有圆角矩形的卡片包裹
4. 路径栏并没有在正确的位置上，需要在刷新按钮后面紧贴着刷新按钮
5. 搜索框、视图、排序、分组按钮全部都不见了，应该紧跟着导航栏下方
6. 单击文件选中依旧没有任何视觉提醒
7. 应用内的图标没有圆角矩形
8. 图片的缩略图不正确（不加载/空白）

此外用户提到"还有很多各种各样的问题，暂时未测出"，需要全量 UI 巡检。

## 2. 方向决策

经 brainstorming 多轮澄清，确定以下方向：

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 对齐基准 | 重新设计（仿访达） | 不再绑定"精修版"设计稿，以 macOS 原生访达为直接参考 |
| 仿访达范围 | 访达风格 + FlowFinder 特性 | 保留双面板、侧边栏品牌区、查重/AI 工具等独有特性 |
| 收藏夹仿访达范围 | 全面仿访达 | 分区 + 蓝色模板图标 + sourceList 选中 + 移除玻璃卡片 |
| 操作区卡片 | 移除卡片，仿访达撑满 | 1px 发丝线分隔左右面板 |
| 工具栏布局 | 双行布局 | Row1=导航+刷新+路径栏；Row2=搜索/排序/分组/视图/工具 |
| 刷新按钮 | 保留 | 放在路径栏之前，路径栏紧贴 |
| 选中样式 | 访达标准选中 | 获焦强调蓝+白字，失焦灰 |
| 标签药丸 | 文件名后内联文字药丸 | 修复裁切问题 |
| 应用图标 | 侧边栏顶部 + 加圆角 | 8pt 圆角矩形包裹 |
| 缩略图问题 | 缩略图不加载/空白 | 排查 QLThumbnailGenerator 调用链 |
| 修复范围 | 8 个问题 + 全量 UI 巡检 | 主动发现其他可见问题 |

## 3. 整体架构策略

采用**分层修复 + 巡检并行**的三层策略：

```
第一层：布局结构重建（根基，必须先做）
  └── 解决问题 3/4/5，为问题 6 扫清布局干扰
       │
       v
第二层：组件级修复（依赖第一层新布局）
  └── 解决问题 1/2/6/7/8
       │
       v
第三层：全量 UI 巡检
  └── 对照访达标准逐屏巡检，发现新问题
```

**设计原则：**
- 保留 Rust Core 与 Bridge 层不动，本轮纯 UI 层修复
- 每个修复点用任务编号注释（延续项目惯例：F1/R1 等）
- 修复后必须通过 Debug 构建验证 + 用户截图验收
- 所有 UI 文案和代码注释使用简体中文
- 主题切换保持 light/dark 二态（无 system 自动跟随）

## 4. 第一层：布局结构重建（问题 3/4/5）

### 4.1 问题3 - 移除操作区圆角卡片

**当前实现（`MainWindowController.swift`）：**
- `createPaneContainer`：`cornerRadius = 12` + `masksToBounds = true`
- `applyPaneBackgroundColor`：白0.15/黑0.25 背景色

**修复方案：**
- `createPaneContainer`：移除 `cornerRadius = 12` 和 `masksToBounds = true`
- 移除 `applyPaneBackgroundColor()` 方法及其调用
- 操作区背景改为透明，让 NSVisualEffectView 的 `.underWindowBackground` 材质直接透出（访达风格）
- 左右面板之间用 1px 发丝线分隔：`paneSplitView.dividerStyle = .thin`，divider 颜色 `NSColor.separatorColor`
- 保留 `FFSplitView` 的 divider 悬停高亮（FlowFinder 特性，不影响访达风格）
- 清理 `MainWindowController.swift:279-282` 残留的"8pt"旧注释

### 4.2 问题4+5 - 双行工具栏布局

**当前实现的问题：**
- `PaneToolbar` 内部是双行结构（Row1 导航 + Row2 工具），总高 72pt
- 但 `MainWindowController.swift:466` 外部约束 `toolbar.heightAnchor = 36` 与内部 72pt 冲突
- 且 toolbar 占 33% / breadcrumbBar 占 67% 同行布局，导致 Row2 被裁切、路径栏位置错

**修复方案 - 重构 paneContainer 内子视图布局：**

```
paneContainer（撑满，无圆角，透明背景）
├── paneToolbar（高 72pt，双行）
│   ├── Row1（高 32pt）：后退 -> 前进 -> 上一级 -> 刷新 -> breadcrumbBar（紧贴刷新，flex 撑满）
│   └── Row2（高 32pt）：搜索框（flex，maxWidth 220）-> 弹性空白 -> 排序 -> 分组 -> 视图切换 -> 工具按钮
├── fileListView（撑满剩余空间）
└── detailsBar（按需显示）
```

**关键修复点：**
- 移除 `toolbar.heightAnchor = 36` 约束，改为 72pt 匹配 PaneToolbar 内部双行结构
- 移除 toolbar 占 33% / breadcrumbBar 占 67% 的同行布局
- `BreadcrumbBar` 从独立容器移入 `PaneToolbar` Row1，紧贴刷新按钮（spacing 4pt）
- Row1 用横向 `NSStackView`，`breadcrumbBar` 设 `huggingPriority = .defaultLow` 让它 flex 撑满
- Row2 沿用现有按钮，确保 `searchContainer` 有 `maxWidth 220pt` 限制
- Row2 的搜索/排序/分组/视图/工具按钮因高度修正而恢复可见

## 5. 第二层：组件级修复（问题 1/2/6/7/8）

### 5.1 问题1 - 收藏夹全面仿访达

**当前实现（`SidebarView.swift`）：**
- 全彩真实位置图标（`NSWorkspace.shared.icon(forFile:)`）
- 包在 `FFGlassView` 玻璃卡片内（cornerRadius=10，material=.sidebar）
- 实心蓝-靛渐变选中

**修复方案：**
- **分区**：按访达风格组织 section header（"个人收藏"、"位置"/"设备"、"标签"），每个 section 有小标题（11pt、semibold、secondaryLabel）
- **蓝色模板图标**：收藏夹项目图标改用 SF Symbols 蓝色模板图标
  - 桌面：`NSImage(systemSymbolName: "desktopcomputer")`
  - 文档：`folder.fill`
  - 下载：`tray.and.arrow.down`
  - 应用程序：`app`
  - 主目录：`house`
  - 设置 `isTemplate = true` + `contentTintColor = NSColor.controlAccentColor`（访达蓝色）
- **sourceList 选中**：`favoritesOutlineView.selectionHighlightStyle = .sourceList`，选中项为半透明蓝高亮
- **移除玻璃卡片**：移除收藏夹外层的 `FFGlassView`，改为直接 `NSVisualEffectView(.sidebar)` 材质（访达侧边栏标准材质）
- 保留拖拽添加、右键菜单等 FlowFinder 特性

### 5.2 问题2 - 标签药丸裁切修复

**当前实现（`FileListView.swift` `configureInlineTagPills`）：**
- 药丸容器 leading 约束为 `greaterThanOrEqualTo`（软约束）
- 文件名超长时药丸被推向右边缘并被列边界裁切
- 药丸背景色 `controlBackgroundColor` 在透明背景上对比度低

**修复方案：**
- 药丸容器 leading 约束从 `greaterThanOrEqualTo` 改为 `equalTo`（硬约束），确保药丸紧贴文件名后 8pt
- 名称列 `textField` 的 `cell.truncatesLastVisibleLine = true` + `cell.wraps = false`，文件名超长时截断而不挤压药丸
- 药丸容器设 `clippingResistance` 防止被列边界裁切
- 药丸背景色改为带标签颜色的浅色：`tag.color.withAlphaComponent(0.15)`，提高对比度
- 保留最多 3 个药丸 + "+N" 计数逻辑

### 5.3 问题6 - 单击选中渲染 bug 排查与修复

**当前实现声称使用标准选中，但实际看不见。** 可能根因及对应修复：

| 根因 | 修复 |
|------|------|
| A. 窗口 key 状态不稳定（透明窗口 + `backgroundColor = .clear`） | 确保窗口 `isOpaque = false` 但 `hasShadow = true`，`becomesKeyOnlyIfNeeded = false`；在 `tableViewSelectionDidChange` 中除 `makeFirstResponder` 外再 `window.makeKey()` |
| B. 透明背景上标准蓝色对比度不足 | `tableView.backgroundColor` 从 `.clear` 改为 `textBackgroundColor.withAlphaComponent(0.6)`，给选中色提供底色衬托 |
| C. appearance 时序问题 | 在 `viewDidLayout` 中显式设置 `tableView.appearance = NSApp.appearance`，确保选中色解析正确 |
| D. `OpaqueContainerView` 定义未使用 | `mainContainer` 改用 `OpaqueContainerView`（已定义但未实例化），修复鼠标穿透 |

采用 `systematic-debugging` skill 逐个验证根因，定位后针对性修复。

### 5.4 问题7 - 应用图标圆角

**当前实现（`SidebarView.swift` `brandIconView`）：**
- 32×32 AppIcon，无圆角包裹，无背景层

**修复方案：**
- 添加 `wantsLayer = true` + `layer?.cornerRadius = 8` + `layer?.masksToBounds = true`
- 添加浅色背景层：`backgroundColor = NSColor.controlBackgroundColor` 作为圆角矩形底色
- 保留 32×32 尺寸和点击弹出关于窗口的交互

### 5.5 问题8 - 缩略图加载链排查

**当前实现（`ThumbnailManager.swift` + `FileListView.swift`）：**
- 使用 `QLThumbnailGenerator` 生成缩略图
- 用户反馈：缩略图不加载/空白

**排查方案：**
- `ThumbnailManager.swift` 排查 `QLThumbnailGenerator` 调用：
  - 确认 `QLThumbnailGenerator.Request` 的 `size`、`scale`、`representationTypes` 参数正确
  - 确认回调在主线程更新 `NSImageView.image`
  - 确认内存缓存（`NSCache`）和磁盘缓存逻辑无死锁
  - 添加日志输出请求/成功/失败链路，便于定位
- `FileListView.swift` 排查 cell 复用时缩略图加载的取消与重用逻辑（避免滚动时旧请求覆盖新 cell）
- 可能根因：请求未发起、回调线程错误、cell 复用竞态、尺寸为 0

采用 `systematic-debugging` skill 系统性定位。

## 6. 第三层：全量 UI 巡检

### 6.1 巡检范围

对照访达标准，逐屏巡检所有 UI 窗口/面板：

1. 主窗口 - 列表视图（左侧 active + 右侧 inactive）
2. 主窗口 - 网格视图
3. 主窗口 - 侧边栏（收藏夹/位置/标签 三个 section）
4. 主窗口 - 面包屑/路径栏交互（同级跳转、点击跳转）
5. 设置窗口 - 各设置面板（外观/通用/标签/高级）
6. 查重扫描窗口 - 扫描进度/分组列表/预览面板
7. 搜索面板 - 搜索条件/结果列表
8. 关于窗口 - 应用信息
9. 文件信息窗口 - 显示简介
10. 批量重命名窗口 - 规则配置/预览
11. 右键菜单 - 文件操作/标签二级菜单
12. 对话框 - 删除确认/连接服务器/标签选择
13. 任务进度对话框 - 长任务进度
14. 详情栏 - 展开收起/预览/元数据

### 6.2 巡检维度

- 视觉一致性（材质、间距、圆角、字号、颜色）
- 交互完整性（点击/悬停/拖拽/键盘）
- 主题适配（浅色/深色二态切换）
- 文案中文化（简体中文）
- SF Symbols 图标完整性

### 6.3 巡检产出

- 问题清单（含截图描述、根因初判、优先级 P0/P1/P2）
- 与用户确认后纳入下一轮修复

### 6.4 巡检方式

- 由于 AI 看不到截图，巡检基于**代码级核对**（对照访达 API 标准用法 + 设计意图）
- 产出代码级问题清单，每条附 `file:line` 证据
- 用户可在巡检完成后用截图补充验证

## 8. 不在本设计范围内

- Rust Core / Bridge 层修改（RC-2 sqlite_cache、RC-3 parallel_ops 等）
- Intel 通用二进制支持
- AI 标签生成引擎
- 大目录性能优化（10万+ 文件）
- 全局撤销/重做栈完善
- SMB 模块

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 问题6 选中渲染有多个潜在根因，可能修复后仍看不见 | 用 `systematic-debugging` 逐个验证，每修一个根因即构建验证 |
| 布局重构可能引入新的约束冲突 | 每步构建验证，保留旧约束注释便于回滚 |
| 巡检发现问题过多导致本轮范围膨胀 | P0 本轮修，P1/P2 下一轮，严格控范围 |
| 仿访达改造影响现有 FlowFinder 特性 | 特性（双面板/查重/AI 工具）单独保留，不混入仿访达改造 |
