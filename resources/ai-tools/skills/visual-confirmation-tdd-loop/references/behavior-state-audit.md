# Behavior State Audit

## Purpose

在给出行为型选项之前，先把「现在到底是什么样」核实到可回溯的证据。它防止两类返工：把已接线的开关误判为失效；在已有同类控件时提出重复方案。

## When

- 设置页、开关、默认值、选择器、删除/移动/覆盖等行为型取舍。
- 方案依赖「这个功能是否已实现 / 是否接线」。
- 用户问「这是什么」「现在是什么样的」「在哪设置」。

## Mandatory Sequence

1. 盘点控件与键。
2. 四路核验事实。
3. 输出事实表。
4. 先给现状可视化。
5. 再给行为型对比稿并只问一个问题。
6. 新事实推翻前提时，作废旧选项并重问。

不要在步骤 1–3 完成前提问或给选项。

## 1. Inventory

- 从设置页代码和其绑定模型建立控件清单，不用过期文档当清单。
- 每项记录：标签、控件类型、默认值、写入 API 与调用点、持久化键、别名/迁移键。
- 同时找孤儿键：有键无控件、有控件无生产读取方、多个控件控制同一行为。

## 2. Four-Route Verification

缺一不可：

1. 常量/枚举键：`rg -n 'enum .*Keys|static let' <sources>`
2. 裸字符串键：把实际持久化字符串、camelCase、snake_case、点分形式一起搜；覆盖源码、plist、`@AppStorage`、`register(defaults:)`。
3. 默认值与写入点：`rg -n 'UserDefaults|@AppStorage|register\(defaults:' <sources>`
4. 生产读取方、生效条件、守卫；风险操作再搜确认弹窗/Sheet/Alert 的调用点。

示例（FlowFinder）：

```bash
rg -n 'startup_location|default_view_mode' FlowFinder
rg -n 'delete_confirm_disabled|deleteConfirmDisabled' FlowFinder
rg -n 'DeleteConfirmDialog' FlowFinder
```

判定规则：

- 零命中只是假设，不是结论。
- 设置页读取值来渲染控件，不算生产消费。
- 测试、fixture、预览、文档只作证据，不算生产读取方。
- 搜索到 getter 还要跟到可观察行为；只读进局部变量不算接线。
- 多个键控制同一行为时，列入现状冲突，不得直接给重复选项。

需要穷举键形式、追踪通知/Combine/服务层、给出 `WIRED_VERIFIED` / `ORPHAN_WRITE` / `FEATURE_DEAD` 等 verdict 时，加载同用户目录的 `settings-wiring-audit`；该 Skill 不可用时按上述四路核验继续。本文件只保留确认前的最低门禁。

## 3. Fact Table

| 控件 | 键的表示形式 | 默认值 | 写入方 | 生产读取方 | 间接传播 | 用户可达路径 | 结论 | 证据(file:line) |
|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  | 已接线/未接线/待验 |  |

- 每一行都要能回到代码或运行记录。
- 没有证据的结论写「待验」，并列出还缺哪一路。
- 不把「待验」带进选项或用户可见结论。

## 4. Current-State Visualization

先展示现状，再展示选项：

- 控件 mock：真实标签、说明文案、当前开关状态。
- 行为矩阵：

| 操作 | 当前结果 | 证据 |
|---|---|---|
| 删除 | 弹窗 / 直接执行 / 不适用 | file:line 或运行记录 |
| 移动 |  |  |
| 双击/打开 |  |  |

- 若已有同类控件或确认弹窗，并列展示；标明两个控件的文案差异和实际控制范围。
- 文案与实际行为不一致时，两者都要显示，不替产品掩盖。

## 5. Behavioral Comparison

每个选项必须同时展示控件状态和操作结果 mock：

- 至少覆盖删除、移动、双击/打开；按功能裁剪并写明裁剪理由。
- 弹窗 mock 写清标题、正文、主/次按钮、是否可撤销。
- 直接执行就明确写「无弹窗」，不要留空让用户猜。
- 选项按钮标签与提问标签逐字一致。
- 一轮只测一个行为轴；多个操作类型属于同一轴时，在一个选项内完整展示。

## 6. Premise Invalidation

触发条件：

- 发现已有同类开关或确认弹窗。
- 发现默认值已与假设相反。
- 发现控件不在已发布界面或没有可达路径。
- 新证据表明已选选项会造成重复控制或行为冲突。

处理：

1. 立即停止沿用旧选项。
2. 决策台账标「作废（前提变更）」，保留原记录。
3. 写入新证据（file:line 或运行结果）和重问轮次。
4. 重新出「现状 + 新选项」对比稿。
5. 重新只问一个问题；不沿用旧标签，不把新事实硬塞进已选方案。

## 7. Evidence Format

报告事实时至少包含：

- 日期、应用版本/构建号。
- 搜索命令与范围。
- `file:line` 或运行证据。
- 未搜索到的表面（动态分发、生成的代码、扩展）与原因。
- 结论等级：已接线 / 未接线 / 待验。

## Anti-Patterns

| 反模式 | 后果 | 纠正 |
|---|---|---|
| 只 grep 常量键 | 把裸字符串接线误判为死键 | 搜所有键表示形式 |
| 把设置页读取当生产消费 | 误判为已接线 | 排除设置 UI |
| 把测试读取当生产读取 | 误判为可用 | 测试只作证据 |
| 只画静态开关 | 用户不知道打开后发生什么 | 现状矩阵 + 操作 mock |
| 发现既有确认后仍沿用旧选项 | 重复控制、二次返工 | 作废、重出稿、重问 |
| 把「待验」写成结论 | 误导用户和实现 | 明确标注待验 |
| 用文字选项问行为 | 用户退回要求可视化 | 先出对比稿再问 |

## Source Case

FlowFinder R-21（2026-10-21 22:48–23:06，会话 `8e8ea484-01b5-4565-8e7c-e1034f1d68a1`）：

- 只按常量键 grep，得出「9 个设置全部只写不读」。
- `startup_location`、`default_view_mode` 实际以裸字符串键在 `MainWindowController` 读取。
- `delete_confirm_disabled` 已由 `DeleteConfirmDialog` 读取，设置页另有「删除前确认」开关。
- 用户退回纯文字选项：「这是什么，现有是什么样的，你要有对应可视化给我选，可视化是固定的要求。」
- 已选「删除 + 移动」与既有删除确认冲突，必须作废并二次出稿。
- 文档结论：真正失效的是 5 个控件 + 2 个孤儿键，完整会话仅缺活动面板。
