# 审计报告模板

## 使用规则

- 先写基线和结论摘要，再写明细；读者要能在第一屏看到 P0 和未验项。
- 每个判断都带证据；没有证据写“未验”，不要用形容词填空。
- 需求 ID 保持来源编号，不重新编号；同一 ID 的不同问题分行写。
- 文档修改与代码修改分开标注，避免“改了文档就算修完”。
- 覆盖矩阵的分母是需求 ID 总数，不是测试总数。
- 报告默认只读；写入文件前先得到用户同意。

## 报告骨架

```markdown
# <项目> 需求 · 代码 · 测试漂移审计

> 日期：<YYYY-MM-DD>
> 仓库：<绝对路径>
> commit：<hash>（工作区：干净 / 有未提交改动）
> 审计范围：<全量 / J1–J5 / 指定模块>
> 文档基线：<REQUIREMENTS 日期 / ACCEPTANCE 日期 / 台账日期>
> 验证基线：<本轮实测 / 沿用台账并标注未重跑>

## 0. 结论摘要

- 需求 ID：<总数>；已审 <n>；未审 <n>
- P0：<n>；P1：<n>；P2：<n>
- 文档过期：<n>；实现但无测试：<n>；写了不生效：<n>；完全未实现：<n>
- 最优先处理：<3 条以内，写 ID 和原因>
- 本轮未验：<n> 项，见 §5

## 1. 审计基线

| 项 | 值 | 来源 |
|---|---|---|
| 版本 / 构建号 | <值> | <文件:行号 / 命令> |
| 分支 / commit | <值> | `git log -1` |
| 工作区状态 | 干净 / 有改动 | `git status --short` |
| 文档版本 | <值> | <文件> |
| XCTest 基线 | <值> | 本轮命令 / 台账（未重跑） |
| 自检基线 | <值> | 本轮日志 / 台账（未重跑） |
| 审计范围 | <全量 / 指定> | — |
| 明确排除 | <项> | — |

## 2. A. 文档漂移

| ID | 来源 | 文档声称 | 代码 / 运行证据 | 判定 | 处置 |
|---|---|---|---|---|---|
| <ID> | <文件:行号> | <原文摘要> | <file:line 或命令输出> | 文档过期 / 部分过期 / 一致 | 改文档 / 改文档并补测试 / 不改 |

**示例（不构成本次结论）**

| ID | 来源 | 文档声称 | 代码 / 运行证据 | 判定 | 处置 |
|---|---|---|---|---|---|
| J1-01 | REQUIREMENTS.md | 6 条权限用途全缺 | Info.plist 已有 5 条，缺 AppleEvents；BreadcrumbBar.swift:483 使用 NSAppleScript | 部分过期 | 补 AppleEvents 并改文档 |

## 3. B. 测试覆盖矩阵

| ID | 旅程 | 需求摘要 | 实现证据 | 自动化证据 | 证据等级 | 覆盖判断 | 缺口 | 建议测试名 |
|---|---|---|---|---|---|---|---|---|
| <ID> | J1 | <一句话> | <file:line> | <测试文件::用例> / 无 | 【断言】/【实机】/【静态】/【未验】 | 完整 / 部分 / 仅手工 / 无 | 实现 / 测试 / 权限 / 无障碍 / 实机 | `test<...>` |

**示例（不构成本次结论）**

| ID | 旅程 | 需求摘要 | 实现证据 | 自动化证据 | 证据等级 | 覆盖判断 | 缺口 | 建议测试名 |
|---|---|---|---|---|---|---|---|---|
| J2-07 | J2 | 搜索范围可切本栏/含子目录/双栏 | PaneState.swift:1289-1297 | 无 | 【静态】 | 无 | 实现 + 测试 | `testJ2SearchFindsFileBeyondThreeLevelsAndReportsTruncation` |
| J4-07 | J4 | VoiceOver 标签与键盘可达 | SidebarView.swift:316 | 无 | 【静态】 | 无 | 无障碍 + 测试 | `testToolPillIsAccessibleAsButtonAndKeyboardActivatable` |

覆盖判断口径：

- **完整**：自动化断言了用户可见行为；必要时另有实机证据。
- **部分**：只有几何、令牌、内部状态、纯函数或旅程的一小段。
- **仅手工**：只有截图、AX、日志或人工操作记录。
- **无**：没有实现证据，或实现存在但完全不可达。

| ID | 问题 | 证据 | 类型 | 处置 | 验收条件 | 依赖 / 需用户决策 |

优先级口径：

- **P0**：核心旅程断裂、虚假发布声明、权限/数据安全/无障碍阻塞、宣称可用但用户完全到不了。
- **P1**：功能断开或只写不读、核心旅程缺行为测试、会误导发布的文档矛盾。
- **P2**：死代码、无行为影响的文档漂移、边缘测试缺口、视觉/维护债。

## 5. D. 未验与需人工确认

| 项 | 为什么未验 | 建议验证方式 | 影响 |
|---|---|---|---|
| <ID / 功能> | <缺权限 / 无法复现 / 只有代码> | <截图 / AX / 实机点击 / 性能采样> | <是否阻塞发布> |

规则：

- “未验”不是“通过”。
- 代码存在但没运行证据，写【静态】或【未验】，不要写【断言】。
- 测试只覆盖纯函数时，不要把它写成用户旅程已验。

## 6. E. 方法与命令

| 检查 | 命令 | 输出 / 计数 | 日期 |
|---|---|---|---|
| 文档 ID 盘点 | `rg -n ...` | <命中数 / 文件数> | <日期> |
| 生产调用方 | `rg -n ...` | <命中数> | <日期> |
| 设置键闭环 | `rg -n ...` | <读写分布> | <日期> |
| FFI 调用方 | `rg -n ...` | <命中数> | <日期> |
| 测试盘点 | `rg -n ...` | <测试方法数 / 类数> | <日期> |
| 自检 | <命令> | <断言数 / 失败数> | <日期> |

补充：

- 命令要能直接复制；路径用变量或绝对路径。
- 如果使用 `rg` 的排除规则，把排除规则写出来。
- 如果只跑了部分测试，明确写“仅跑单项，全量未重跑”。

## 7. 完整性自检

- [ ] 需求 ID 清单的分母与覆盖矩阵一致
- [ ] 每个 ID 都有结论或“未审”
- [ ] 每条结论都有 `file:line` 或命令输出
- [ ] 文档漂移与代码问题没有混为一行
- [ ] 覆盖矩阵区分了自动化、实机、静态和未验
- [ ] 每个 P0/P1 都有验收条件
- [ ] 未验项单独列出，没有被“已完成”覆盖
- [ ] 测试数字来自本轮或明确标注未重跑
- [ ] 报告锚定 commit/日期
- [ ] 审计期间没有修改代码、文档或提交

## 8. 交付说明

报告末尾写清：

    本轮只做只读审计，未修改代码/文档，未提交。
    建议下一步：先处理 P0 的 <ID>；P1 按 <批次> 拆分；P2 留到收尾。
    需要你决定：<范围 / 删除 / 接线方式 / 是否保留某入口>。

```

修复阶段按用户批准的批次执行，使用 TDD；修复完成后用 `flowfinder-docs-sync` 同步台账与交接，不把审计报告当成完成凭据。
