# Visual Confirmation Loop

## 目标

让用户通过“看”和“点”做决定，而不是靠文字想象。每轮只呈现一个决策、一张真实比例的可操作稿、一个问题；用户明确选择后，才进入实现。

## 何时使用

- UI、布局、间距、字体、颜色、图标、接缝、交互或文案存在取舍。
- 需要 A/B/C 选项、现状与改法对比、对齐或尺寸校准。
- 实现任何用户可见的视觉改动之前。
- 用户说“做可视化”“出对比稿”“让我选”“确认设计”“一次只问一个”。
- 不适用：纯逻辑、接口、数据结构等没有视觉维度的决策，直接用文字和表格。

## 核心循环

### 1. 锁定本轮唯一决策

用一句话写明：“本轮只定 X，Y 和 Z 固定不动。”列出 2–4 个真正可行的选项。列不出选项时，先问一个澄清问题，不要先做图。把已确认的部分写成冻结项，后续轮次不得悄悄改掉。

### 2. 取真实基线

从当前应用截图、代码或设计令牌中取真实尺寸和颜色：窗口大小、面板宽度、字体、内边距、圆角、色值。未知量必须标成“假设”，不得伪装成实测。

### 3. 按 1:1 建稿

优先使用当前环境的内联可视化能力（如 `present_visualization`）；没有就生成单文件 HTML 并展示。画框必须等于真实窗口或组件尺寸，并标注比例，例如“1:1 · 1060×700”。小几何细节（6pt 接缝、2pt 描边）用内嵌放大镜做 1:1 特写，不要把整张图缩小后再判断。

### 4. 让每个状态可操作

每个选项一个控件；切换只改当前轴，其他轴冻结。定性差异适合并排，状态多或空间窄时用开关。每个选项配一行取舍说明，写清代价，不只写优点。

### 5. 展示前自测

逐个点击所有控件，包括点文字和图标子元素；确认可见状态、`aria-pressed` 或根节点状态确实变化；检查控制台、遮挡和错位。任何控件无效，先修好再展示。没亲自操作过的交互不得发出。

### 6. 一次只问一个问题

使用当前环境的单选提问工具（如 `AskUserQuestion`）或直接提问。问题必须包含选项与一行取舍。禁止“这样可以吗”式空问，禁止把多个决策打包进同一个问题。

### 7. 迭代与锁定

只重做有争议的部分，保留已确认值。用户明确选择后，把结论改写成具体值（pt/px、色值、行为、层级），再开始实现。用户没有点名选项时，不把“不错”“采纳推荐”当作选择，必须追问具体选项。

## 常用骨架

### 对比稿

A/B/C 用同一画布切换，子变体用 A1/A2/A3 命名。控制组按轴分组（样式、接缝、侧栏、面板），但本轮问题只问其中一个轴。标题下方固定显示“选项 + 代价”。

### 编号解剖图

给争议部位编号 1..n，配图例按钮；点击图例高亮对应元素。只标争议部位，不把整屏都画满引线。

### 中心线与 Δ 标注

画水平或垂直虚线基准线，实时显示“Δ 0pt · 对齐”或“Δ 2pt · 红绿灯偏低”。允许用户微调偏移，确认可接受阈值。

### 前后对比

固定其他变量，只切换“现状/新设计”，并保留收起/展开、侧栏显隐等关键状态可切换。

## 关键实现坑

### 根节点状态属性劫持事件委托（真实踩坑）

**症状**：点击子选项无反应，且没有控制台报错。

**根因**：根节点也带 `data-style`，处理器用 `event.target.closest('[data-style]')` 查找。点击接缝按钮（`data-seam`）时，`closest` 会一路爬到根节点，返回根节点本身；第一段处理器于是把状态重设为根节点的旧值并提前 `return`，接缝选项 A2/A3 永远轮不到自己的分支。

**修法**：根节点只存激活态，选项控件才带选项值；查询必须限定控件类型，每个轴独立处理。

```html
<div id="preview" data-active-style="weld">
  <button type="button" data-style="weld" aria-pressed="true">A 焊死式</button>
  <button type="button" data-style="float" aria-pressed="false">B 悬浮</button>
  <button type="button" data-seam="soft" aria-pressed="false">A2 柔和接缝</button>
</div>
<script>
  const root = document.getElementById('preview');
  root.addEventListener('click', (event) => {
    const styleBtn = event.target.closest('button[data-style]');
    if (styleBtn) {
      root.dataset.activeStyle = styleBtn.dataset.style;
      root.querySelectorAll('button[data-style]').forEach((btn) => {
        btn.setAttribute('aria-pressed', String(btn === styleBtn));
      });
      return;
    }
    const seamBtn = event.target.closest('button[data-seam]');
    if (seamBtn) {
      root.dataset.activeSeam = seamBtn.dataset.seam;
      root.querySelectorAll('button[data-seam]').forEach((btn) => {
        btn.setAttribute('aria-pressed', String(btn === seamBtn));
      });
    }
  });
</script>
```

CSS 也必须用 `#preview[data-active-style="weld"]`，不能用 `[data-style="weld"]` 同时匹配根和控件。

**验证**：逐个点击按钮，并从按钮内的 SVG 或文字子元素再点一次；断言根节点对应 `data-active-*` 与 `aria-pressed` 都变化。

### 用缩略图判断小几何

缩略图会把 1pt 描边和 6pt 接缝抹平。整屏看比例，细节用 1:1 特写看。

### 一次暴露太多轴

控件可以多，问题只能一个。不要在一轮里同时问样式、间距、颜色和层级。

### 把“修正执行”误判成“更换模型”

用户说“在现有基础上改”时，通常问题在视觉语言不一致或信息层级混乱，而不是结构模型错误。此时冻结结构，只重做视觉与层级，不要强推新模型。先确认问题属于“模型不对”还是“执行不一致”。

## 发送前检查

- [ ] 本轮只有一个决策、一个问题。
- [ ] 稿子是 1:1，并标了真实画框尺寸。
- [ ] 有 2–4 个选项，每个都写了代价。
- [ ] 所有控件可用，含从子元素点击。
- [ ] 未涉及的轴已冻结并标注。
- [ ] 几何争议处有编号、中心线或 Δ 标注。
- [ ] 控制台干净，自测通过。
- [ ] 用户明确选择前没有开始实现。
- [ ] 结论已改写成具体值。
