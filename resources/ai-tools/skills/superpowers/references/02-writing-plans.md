# 写实施计划（writing-plans）

计划是给「一个热情但品味差、没判断力、没有项目上下文、且讨厌写测试」的初级工程师看的——它必须清楚到对方照做不会跑偏。

## 计划的结构

把工作拆成**每个 2-5 分钟可完成**的小任务。每个任务必须包含：

```
### 任务 N：<一句话目标>
- 文件路径：src/foo/bar.ts（精确到文件）
- 要做的：<完整、可粘贴的代码或明确改法>
- 验证：<具体命令或断言，例如 `npm test foo` 应通过>
```

## 硬约束

- **YAGNI**：只写被要求的，不提前造「以后可能用到」的东西。
- **DRY**：重复逻辑抽出来，但不过度抽象。
- **可验证**：每个任务都有「怎么知道做完了」的办法。
- **无歧义**：文件路径、函数名、改哪几行，全部写死。

## 反例（不要这样写计划）

```
- 优化一下性能
- 把那块逻辑重构好
```

## 正例

```
### 任务 3：给 calculateTotal 加折扣分支
- 文件路径：src/cart/price.ts
- 在 calculateTotal() 第 42 行后插入：
    if (coupon) total *= 1 - coupon.rate;
- 验证：新增测试 `coupon 应用时总价打 9 折` 应通过
```

## 写完后

把计划呈现给用户确认，再进入子代理驱动开发。计划变了就回头改计划，不要悄悄改。
