## 1. 证据台账

```text
| ID | 界面/状态 | 已确认期望 | 实际观察 | 回归测试 | 修复 | 真机证据 | 状态 |
|----|-----------|------------|----------|----------|------|----------|------|
| U-01 | <界面/状态> | <规格/决策> | <截图/日志> | <测试名/命令> | <改动> | <截图/日志路径> | Verified / Unverified / Blocked |
```

规则：

- 一行只对应一个可独立验收的缺陷。
- 不写“整体 UI 已修好”这类聚合行。
- 每行至少有一个可复查的证据：测试输出、截图路径、自检日志、产物哈希。
- 用户改口时把旧决策标为 `superseded`，同步更新受影响的行。

## 2. 圆角与卡片层级

实施检查：

- [ ] 规格圆角 token：`<...>`；活动/非活动是否允许差异：`<...>`
- [ ] 左右/上下差异是否跟随活动态：切换活动面板后，直角是否移动？`<结果>`
- [ ] 四角（左上/右上/左下/右下）在固定窗口尺寸下逐一检查
- [ ] 缩放、全屏、还原、多窗口下复验
- [ ] 外层卡片与内层容器的 `cornerRadius`、`masksToBounds`、content inset 一致
- [ ] 没有单角直角、双重裁切、内容被裁、圆角被父视图覆盖
- [ ] `cornerCurve` 仅按规格使用；没有为了“看起来圆”而猜数值

测试钩子：

- [ ] 纯逻辑测试：圆角归属策略、活动/非活动差异策略
- [ ] 应用内自检：打印实际 `cornerRadius`、`masksToBounds`、frame
- [ ] 视觉归因：需要层归因时使用 `appkit-visual-effect-verification`

真机证据：

- [ ] 固定几何的四角裁剪图，浅色/深色各一组
- [ ] 活动面板与非活动面板各一组
- [ ] 差异有规格解释，而不是“左边看起来就是这样”

完成条件：四角符合已确认策略；活动/非活动差异有依据；无裁切或重复圆角。

## 3. 双面板与详情

实施检查：

- [ ] 仍是两个独立面板卡片，详情在面板内；没有擅自加入全局栏或合并卡片
- [ ] 面板间距/分隔线没有把两张卡视觉粘成一张
- [ ] 窄窗口、单面板模式、还原双面板后布局正确
- [ ] 活动态强调不压过内容，不降低文字对比
- [ ] 详情区：长路径、缺失元数据、折叠/展开、选中/焦点/非活动
- [ ] 详情区背景、标签、分隔线在浅色/深色下都可读

测试钩子：

- [ ] 几何自检：卡片边界、间距、详情区宽度
- [ ] 状态测试：单/双面板切换后卡片数量与布局不变量

完成条件：结构符合已批准拓扑；两种外观、两种面板状态下都无遮挡/错位/低对比。

## 4. 工具栏

实施检查：

- [ ] 分组、间距、分隔线、溢出菜单符合规格
- [ ] 没有重复控件或重复命令
- [ ] 按钮有可访问标签；图标与文字对齐
- [ ] 可用性随 key window、选中项、权限状态更新
- [ ] 工具栏控件没有抢占应用级快捷键
- [ ] 窄窗口下不挤压搜索框/面包屑/标签条

测试钩子：

- [ ] 菜单/控件盘点测试：命令与快捷键唯一归属
- [ ] 自检：工具栏高度、控件 frame、无重叠

完成条件：两种外观、窄/宽窗口、有无选中项下均可用且无重叠。

## 5. 搜索

实施检查：

- [ ] 焦点环可见，浅色/深色都可见
- [ ] 占位、清除按钮、取消/退出行为正确
- [ ] 空、无结果、错误、加载状态齐全
- [ ] 键盘路径：Tab/⌘F/Esc/Return 不与全局快捷键冲突
- [ ] 搜索是局部能力时，没有扩成全局搜索栏
- [ ] 结果列表与详情区布局稳定，无跳动

测试钩子：

- [ ] 状态机测试：空/输入/无结果/错误/清除
- [ ] 菜单测试：⌘F 等快捷键只有一个归属

完成条件：关键状态在两种外观下都有截图；键盘可完成一次完整搜索与清除。

## 6. 查重

实施检查：

- [ ] 空闲、扫描中、有结果、无结果、错误、取消状态齐全
- [ ] 进度/取消可用，不阻塞主线程
- [ ] 结果选中、详情、批量操作符合规格
- [ ] 结果出现/消失时布局稳定，无突然跳动
- [ ] 强调色克制，没有用大面积高饱和色压过内容
- [ ] 复用窗口时主题/外观正确

测试钩子：

- [ ] 状态机测试：扫描开始/完成/取消/失败
- [ ] 复用测试：关闭重开、扫描中切主题

完成条件：全状态可复现；两种外观下结果与空态都可读；无布局抖动。

## 7. 辅助窗口

实施检查：

- [ ] 单例/复用窗口每次显示都重新应用外观
- [ ] 没有把 `NSColor`/`CGColor` 静态缓存到初始化路径
- [ ] 首次显示、关闭重开、打开时切主题、关闭时切主题都正确
- [ ] 深色下没有白底白字；浅色下没有低对比
- [ ] 背景、标签、分隔线、控件、焦点环都跟随外观
- [ ] 窗口 key/non-key 状态下的控件可用性正确
- [ ] 窗口尺寸/位置记忆没有污染测试或真实偏好

测试钩子：

- [ ] 视图/窗口测试：强制 `.aqua` 与 `.darkAqua` 后断言解析色
- [ ] 复用循环：show → close → show，两种外观各一次
- [ ] 若实例化生产窗口控制器，先应用 `macos-xctest-isolation`

完成条件：两种外观 × 首次/重开/切主题的矩阵都有证据；无白底白字。

## 8. 菜单与快捷键

实施检查：

- [ ] 主菜单、上下文菜单、工具栏菜单的 `keyEquivalent` 全部盘点
- [ ] 同一快捷键只有一个归属
- [ ] 右键菜单没有应用级快捷键（如 ⌘I）
- [ ] 命令走 responder 链，目标/动作在正确响应者
- [ ] 有选中/无选中、key/non-key window 下启用状态正确
- [ ] 移除冲突键位后，命令仍有可达入口

测试钩子：

- [ ] 菜单构造测试或应用内自检：快捷键归属唯一
- [ ] 实际按键冒烟：在编辑器/列表/空白区分别触发

完成条件：快捷键清单与规格一致；没有菜单项抢占；命令可达。

## 9. 主题迁移与外观

实施检查：

- [ ] 迁移有版本号，不只是一个布尔标记
- [ ] 迁移会重算/重应用 token 和派生色，而不是只翻标记
- [ ] 旧键清理有备份，且只删除已确认的键
- [ ] 没有删除整个 defaults domain
- [ ] 动态 `NSColor` 没有被提前解析成静态 `CGColor`
- [ ] `viewDidChangeEffectiveAppearance` 与每次显示都会重新应用
- [ ] 启动、切换主题、重启后都读取实际持久化值验证

测试钩子：

- [ ] 旧偏好 fixture：写入旧版本/旧粉色，运行迁移，断言新值和解析色
- [ ] 重启验证：退出应用后读取 defaults，再启动截图
- [ ] 浅色/深色切换：窗口打开时与关闭时各一次

完成条件：旧偏好样本迁移后无残留色；两种外观都正确；备份与清理范围可追溯。

## 10. 空态、错误、焦点与无障碍

- [ ] 空、加载、错误、禁用、权限不足状态都有可读反馈
- [ ] 焦点顺序合理，键盘可到达主要操作
- [ ] 文字对比在浅色/深色下可读
- [ ] 图标按钮有可访问标签
- [ ] Esc、Return、默认/取消按钮行为符合 macOS 习惯
- [ ] 焦点环不被裁切，不被发光/阴影掩盖

## 12. 常见误判

- 代码里写了 12pt，就认为真机一定是 12pt：错，必须看真实窗口。
- 单测通过，就认为视觉正确：错，单测只能证明非视觉护栏。
- 版本号相同，就认为桌面副本是同一构建：错，至少比对可执行文件哈希。
- 迁移标记已置位，就认为主题已正确：错，检查实际持久化值和解析色。
- 右键菜单的 `keyEquivalent` 无害：错，盘点并消除重复归属。
- 左右圆角不同一定是 bug：不一定，先看是否跟随活动态，再回到规格。
- CUA 报错就是产品 bug：不一定，先按 bundle id 重连并重建 AX/截图基线。
- “所有界面都看过了”：只有逐屏证据齐全时才能这样说。
