# 核验台账模板

## 台账表

| 来源 ID | 原声明（原子） | 类型 | 判定 | 证据 | 原严重度 | 修正严重度 | 完成状态 | 动作 | 残留风险/下一步 |
|---|---|---|---|---|---|---|---|---|---|
| UI-Bug 01 | Tab 聚焦工具行时不绘制焦点环 | 缺陷 | 属实 | `ToolPage.swift:164` 的 hover guard 先于 firstResponder 分支；实机 Tab 复现 | P0（外部） | P2（无障碍，无数据/核心流程影响） | 未开始 | 修复 | 修复后实机复查焦点环 |
| UI-Bug 08 | 三态主题按钮文字色不跟随刷新 | 缺陷 | 未验 | 代码将 `labelColor` 固化进 `attributedTitle`，但动态色是否自动跟随需实机确认 | P2 | P2（暂定） | 未开始 | 验证 | 深色模式截图确认文字色 |

类型可选：缺陷、严重度、完成声明、范围/影响、设计偏好。

完成状态可选：未开始、已实现未验证、部分验证、已验证、与声明不符、不适用。

动作可选：修复、验证、合并、拒绝、观察。

证据至少包含一项：`path/to/file:line`、命令输出、测试结果、实机截图/日志、AX 树或测量数据。记录证据对应的构建或提交。

## 判定标准

| 判定 | 含义 | 证据要求 |
|---|---|---|
| 属实 | 所述行为能够复现或由代码路径直接证明 | 直接证据；UI/行为类优先运行时证据 |
| 部分属实 | 核心主张成立，但范围、影响或根因有偏差 | 说明成立部分与偏差部分 |
| 不属实 | 有证据与主张矛盾 | 反证；不能只写“没找到” |
| 未验 | 证据不足、无法复现或自动化受阻 | 阻塞点、所需环境、下一步验证方法 |
| 重复 | 与已有条目相同 | 链接已有 ID |
| 不适用 | 前提与当前产品或架构不符 | 说明前提差异 |

## 严重度标准

- **P0**：数据丢失或损坏、崩溃、安全或隐私问题，或核心流程对所有用户完全阻断且无绕行。
- **P1**：主要工作流明显退化、较常见，或绕行成本高。
- **P2**：局部视觉、文案、无障碍或低频边界问题，不影响核心任务完成。

外部严重度只作为输入。重评时必须写出用户影响证据和升降级理由。代码级缺陷但影响未实测时，严重度标为暂定。

## 完成状态阶梯

1. 文档声称完成。
2. 代码存在。
3. 测试存在。
4. 测试断言了目标性质。
5. 运行时或实机观察到目标行为。
6. 回归基线通过。

只有同时达到 5 和 6 才能写“已验证”。达到 2–4 写“已实现未验证”或“部分验证”。AX 虚拟化、性能和平台行为必须达到 5，且证据是实测数据而非代码推断。

## 合并规则

| 核验结论 | 计划动作 |
|---|---|
| 属实 | 建修复任务，附来源 ID、严重度、证据 |
| 部分属实 | 建修复任务，同时列出需要补验的偏差 |
| 未验 | 建验证任务，写阻塞点和确认方法 |
| 重复 | 合并到已有条目，保留来源 ID |
| 不属实 | 记录反证和拒绝理由，不排期 |
| 不适用 | 记录前提差异，不排期 |

- 保留内部已有 P0，不因外部清单未提及而删除。
- 排序为 P0、P1、P2；外部批次划分不自动成为执行顺序。
- 输出计划增量，不重写整份计划。
- 所有外部 ID 必须被映射、合并或说明，不得静默丢弃。

## 修正摘要模板

```text
确认：N
部分属实：N
不属实：N
未验：N
重复：N

严重度修正：
- <ID>：<原级别> -> <修正级别>；理由：<影响证据>

进度声明修正：
- <条目>：<原声明> -> <实际状态>；理由：<运行时证据>

计划增量：
- P0：...
- P1：...
- P2：...

未验/Blocked：
- <ID>：<阻塞点>；下一步：<验证方法>
```

## 简短示例

外部意见给出两条判断：

1. “焦点环缺失，P0。”
2. “AX 虚拟化已完成。”

核验后：

- 焦点环缺失：代码路径属实，实机可复现；但不会造成数据丢失或核心流程阻断，降为 P2 无障碍，进入 P2 修复。
- 主题按钮文字色：代码看起来可疑，但动态色行为需要深色模式截图，标“未验”，先建验证任务。
- AX 虚拟化：文档写完成，但独立副本 AX 树仍暴露每行 cell 并出现重复行；降为“部分完成/待修”，按 P1 进入修复，不能按已完成计。

结论必须同时给出证据、修正严重度、完成状态和计划动作；不要把外部报告的严重度和完成声明直接复制进计划。
