# 实现（驱动 TDD 构建）

按规格说明或任务集**执行**构建——通过 TDD、类型检查和完整测试套件驱动，最后审查并提交。

**不决定做什么。** Spec 已定、接缝已选——本技能是执行计划，不是重新打开它。是手，不是脑——思考在上游已经发生。

## 预定义接缝

核心概念是**接缝（seam）**——功能被测试的稳定接口，在写代码之前就选好。
- 不在构建中途发明接缝
- 使用上游（to-spec 阶段）已选定的接缝
- 通过 tdd 在接缝处写测试

在预定义接缝处工作保证实现诚实：测试靶心是持久的，底层代码可以动而测试不用动。

## 执行循环

```
对每个任务（按阻塞顺序）：
  1. 读取任务描述和验收标准
  2. 驱动 /tdd：红-绿循环逐行为构建
  3. 类型检查通过
  4. 单文件测试通过
  5. 进入下一个任务

全部任务完成后：
  6. 跑完整测试套件
  7. 执行 /code-review 审查
  8. 审查通过 → 提交到当前分支
```

## 紧凑循环节奏

- 频繁类型检查（每写完一个逻辑单元就跑）
- 边写边跑单文件测试
- 最后跑一次完整套件
- 审查通过后提交

## 工作流定位

```
grill-with-docs → to-spec → to-tickets → implement → code-review
```

本技能是构建链倒数第二步。上游是 `to-tickets` 产出的任务集，内部驱动 `tdd`，收尾调用 `code-review`。
