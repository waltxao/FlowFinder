# 规格 → 示踪弹任务

将规格说明、计划或当前对话拆分为一组**任务（ticket）**——每个都是一颗示踪弹（tracer bullet）：一个薄的**垂直切片**，端到端贯穿所有集成层。

## 核心原则：垂直切片，不是水平切片

- **水平切片**（错误）：一个任务只做一层——全部数据库、全部API、全部UI——所有层落地前什么都不能用。
- **垂直切片**（正确）：一个任务切穿**每一层**的一条窄路径——schema + 逻辑 + UI + 测试——完成即可演示/验证。

每颗示踪弹完成后可以独立 demo 或验证，这才是安全交给实现环节的前提。

## 阻塞关系

每个任务必须声明它被哪些任务阻塞（Blocked by）。这使任务集有两种读法：
- **顺序执行**：按编号从上到下，阻塞者先做
- **并行执行**：任何阻塞者全部完成的任务都在"前沿"，可以开工

## 输出格式

任务写入 `.scratch/<功能名>/tickets/` 目录，每个任务一个文件：

```
.scratch/用户认证/tickets/
├── 001-数据库schema.md
├── 002-注册接口.md（Blocked by: 001）
├── 003-登录接口.md（Blocked by: 001）
└── 004-登录UI.md（Blocked by: 003）
```

每个任务文件格式：

```md
# {任务标题}

**Blocked by**: {前置任务编号，无则写"无"}

## 目标
一句话说清这个切片完成后用户能做什么/验证什么。

## 涉及层
- [ ] 数据层：...
- [ ] 逻辑层：...
- [ ] UI层：...
- [ ] 测试：...

## 验收标准
- 可验证的具体条件1
- 可验证的具体条件2
```

## 工作流程

1. **预重构（Prefactoring）**：先找"让变更变容易"的前置工作，排在最前面
2. **切片**：按垂直切片原则拆分，先出草案
3. **确认**：向用户确认粒度、阻塞关系、是否需要合并/拆分
4. **输出**：用户确认后写入文件，阻塞者编号在前

## 宽重构例外

当变更是**宽重构**（重命名列、改共享类型）——爆炸半径横跨整个代码库，无法垂直切片时，改用**扩展-收缩**模式：
1. **扩展**：新形式与旧形式并存，不破坏任何东西
2. **迁移**：按批次移动调用点，每批一个任务，全程保持绿色
3. **收缩**：所有调用点迁移完毕后删除旧形式

## 工作流定位

```
grill-with-docs → to-spec → to-tickets → implement → code-review
```

本技能在 spec 之后、实现之前。产出的任务供 `implement` 逐个构建。
