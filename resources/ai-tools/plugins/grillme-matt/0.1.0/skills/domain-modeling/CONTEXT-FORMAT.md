# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{一两句话描述这个上下文是什么、为什么存在。}

## 语言

**订单**:
客户提交的一次购买请求，包含一个或多个商品项。
_避免_: 购买单, 交易

**题目**:
一道独立的练习题，包含题干、选项、正确答案和解析。
_避免_: 问题, 试题, 习题

**用户**:
使用本应用进行刷题学习的个人。
_避免_: 客户, 学员, 账号
```

## 规则

- **有主见。** 同一概念有多个叫法时，选最好的一个，其余列入 `_避免_`。
- **定义精炼。** 最多一两句话。定义它**是什么**，不是它做什么。
- **只收录项目特有术语。** 通用编程概念（超时、错误类型、工具模式）不属于这里，即使项目大量使用。添加前自问：这是本上下文独有的概念，还是通用编程概念？只有前者才属于这里。
- **自然聚类时分组。** 如果所有术语属于同一内聚领域，平铺即可。

## 单上下文 vs 多上下文

**单上下文（多数项目）：** 根目录一个 `CONTEXT.md`。

**多上下文：** 根目录 `CONTEXT-MAP.md` 列出各上下文及其关系：

```md
# 上下文地图

## 上下文

- [刷题](./src/practice/CONTEXT.md) — 题目展示、作答、判分
- [错题本](./src/mistakes/CONTEXT.md) — 错题收集与复习
- [统计](./src/stats/CONTEXT.md) — 学习数据分析

## 关系

- **刷题 → 错题本**: 答错的题目自动推送到错题本
- **刷题 → 统计**: 每次作答结果写入统计模块
```

推断规则：
- 存在 `CONTEXT-MAP.md` → 读取它找到各上下文
- 只有根 `CONTEXT.md` → 单上下文
- 都不存在 → 第一个术语确定时惰性创建
