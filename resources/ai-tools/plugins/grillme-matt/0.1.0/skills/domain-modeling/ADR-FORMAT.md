# ADR 格式

ADR 存放在 `docs/adr/` 下，按顺序编号：`0001-简短描述.md`、`0002-简短描述.md`。

目录不存在时，在第一条 ADR 需要写入时才创建。

## 模板

```md
# {决策的简短标题}

{1-3句话：背景是什么，我们决定了什么，为什么这样决定。}
```

就这么简单。ADR 可以只有一段话。价值在于记录**做了什么决策**和**为什么**——不在于填满各种章节。

## 可选章节

仅在确实有价值时添加，大多数 ADR 不需要：

- **状态**（proposed | accepted | deprecated | superseded by ADR-NNNN）— 决策被重新审视时有用
- **备选方案** — 仅当被否决的方案值得记住时
- **后果** — 仅当存在非显而易见的下游影响时

## 编号规则

扫描 `docs/adr/` 中现有最大编号，加一。

## 何时提议记录 ADR

以下三条必须**全部满足**：

1. **难以逆转** — 改主意的代价显著
2. **无上下文会困惑** — 未来读者看到代码会想"为什么这样做？"
3. **真实取舍** — 存在真正的备选方案，因具体理由选了一个

### 典型适用场景

- **架构形态**："用 monorepo"、"写模型用事件溯源，读模型投射到 SQLite"
- **上下文间集成模式**："模块间通过事件通信，不用同步调用"
- **带锁定效应的技术选型**：数据库、认证方案、部署目标
- **边界与范围决策**："用户数据归用户模块所有，其他模块只能通过 ID 引用"
- **刻意偏离显而易见路径**："不用 ORM 而用原生 SQL，因为 X"
- **代码中看不到的约束**："因为离线要求不能用云服务"
